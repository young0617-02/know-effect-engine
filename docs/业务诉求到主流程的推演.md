## 1. 业务诉求：六条痛点，归约成三个硬要求

基准行业是**数字技术服务 / IT 服务与数字化运营**——咨询、实施、运维全生命周期交付，
聚焦金融 / 能源 / 化工，前向部署工程师（FDE）要驻客户现场。这个形状决定了痛点的性质：

| 痛点 | 它真正要求什么 |
|---|---|
| 数十年知识资产散落项目文档、随项目结束沉睡 | 检索要能跨项目命中，且**结果可核对** |
| 跨行业 / 跨项目经验难复用，重复造轮子 | 复用不能靠"搜到就行"——**错行业的方案被当真方案用**比搜不到更糟 |
| FDE 现场取数慢，靠呼叫总部专家，响应以小时计 | 秒级；但**慢的正确答案 < 快的错误答案**在这里不成立，反过来才成立 |
| 新人上手周期长 | 答案要自带出处与口径，否则学不到"依据从哪来" |
| 内网、客户数据涉密，**不能出域** | 纯云方案当场被否 → 只能本地推理 |
| 答案无出处，员工"不敢信、不敢用" | **这一条是全局枢纽**（见下） |

**归约结果**——六条痛点其实只压出三个硬要求：

1. **可溯源**：每条结论必须有出处，且出处能核到"哪份文档 / 哪一章 / 第几页 / 哪一块"。
2. **可隔离**：可见范围由身份决定，且强制点在**检索层**（不是拿到结果后再遮）。
3. **可度量**：整条链路的质量要能用一把**别人也能复算**的尺子量出来，否则"效果不错"只是自述。

> **为什么"可溯源"是枢纽**：前四条痛点（复用、取数、上手、口径一致）的解法都是"把知识搬进可检索的库"，
> 这一步任何 RAG demo 都能做。真正决定这套东西能不能进交付流程的是**员工敢不敢照它说出去**——
> 而"敢"的前提是可核对。所以本项目后面所有看起来"过度设计"的部分（引用强制、无依据必拒、
> 规则分不叫概率、双人标注、审计不可篡改），**根都在这一条上**。

## 2. 从"可溯源"推出可信三件套

"有出处"和"出处可信"不是一回事。顺着这条往下推，会掉出三个必须自己实现、模型给不了的机制：

| 推演 | 落成的机制 | 代码位置 |
|---|---|---|
| 模型会编一个看起来很合理的引用 | **引用强制**：每条要点/结论必须映射到真实证据块，映射不上的**丢掉该要点**而不是保留文字 | `qa/answer.py` enforce 节点 |
| 证据不足时模型仍会"尽力作答" | **无依据必拒**：检索分不过闸 → 直接拒答，不进生成；进了生成而模型自宣无依据 → 走另一条出口 | `graph.py` `retrieval_gate` / `model_declared_no_evidence` |
| 模型自评的"置信度"不是概率，会被下游当概率用 | **分数降格为规则分**：复合分由检索强度 / 引用一致性 / 模型自评加权算出，响应里自带 `score_basis=rule_composite_not_probability` | `qa/answer.py:99` |

第三条是被实测逼出来的，不是设计时想到的：早期版本想让这个分数承担"预测正确率"的职责，
用温度缩放去校准它。结果发现**全部 gold 标签在这个语料上零方差**（人人都是"答对了"），
拟合出来的 T=6.655 是退化产物（NLL 最优即 T→∞、输出基率）。于是：
判据换成真人逐块标注 + `answer_correct` 正确性工单，分数**明确不叫概率**，校准只作报告值。
现在 ECE 实测 **0.2006 > 0.10（不达标）**，方向是**欠置信**（模型自评 0.7671 < 实际 0.9677）——
不危险的那一边，但也没被"项目完成了"这句话抹掉。

## 3. 从"内网 + 8GB + 一个人"推出技术形态

约束不是背景板，它直接砍掉了半张选型表：

- **不出域** → 生成/嵌入/重排全在本地。云端兜底这条路径**代码里有、开关是关的**
  （`cloud_fallback_enabled=false`），且 ⑥ 实测过容器封公网 + 宿主审计 0 出网。
- **8GB 显存** → 7B 常驻 + BGE-M3 嵌入 + BGE-reranker 共存，实测峰值 **8098/8188 MiB、零 OOM、零余量**。
  所以必须锁死嵌入批大小与生成上下文长度；所以**跑验证脚本前要先停 API**（两个 CUDA 上下文抢不到显存，
  会**静默**退化成单腿检索——见第 6 节）。
- **容器化只能带 CPU torch** → 实测合成一次检索 CPU+float32 = **5167ms**，而门禁是 P95 检索 < 800ms。
  于是拓扑定成"存储 + 前端进容器、推理与 API 在宿主"（ADR-12），代价明说：
  **「整机拔网线还能不能问答」不在承诺范围内**。
- **没有公开评测集**（企业内网文档不外发）→ 只能自建评测集，且自建尺子的可信度必须外部证明
  → 双人标注 + Cohen's Kappa（见第 4 节）。
- **一个人开发** → 每阶段要有**可判定出口**，不设无限期；所以有 Gate 0 六道门禁、M0–M5 里程碑、
  以及"哪些不做"的第七节。

## 4. 从"可度量"推出评测集，再从评测集推出它自己的尺子的尺子

这条链是本项目最绕的一段，但它是"可度量"这个要求的必然代价：

```
要量化检索质量
  → 需要 qrels（每题哪些块算相关）
  → 语料是我自己写的、题也是我自己出的 ⇒ 我算的 gold 不能自证
  → 引入第二评审，逐块判「这块能否独立答全该题」（判据经三次裁决定稿）
  → 候选池 547 行 + 三批重标 124/19/10 行，全部真人填
  → 读数：改尺前独立盲标 vs strict Kappa 0.8593；合并 0.8475
  → 顺带照出：section 口径 0.6091，比 strict 低 0.2472（CI 不含 0）
    ⇒ 「宽松 gold 是把注水尺子」由外部人复现，不是我自己说的
```

于是**门禁只认 strict gold**（一块必须能独立答全该题），section 口径降级为报告值。
这条选择的代价写在文档里：section 的 Recall@5 只有 **0.8374**，比 strict 的 0.9779 难看很多，
但它是"检回来的东西真的回答了这个问题"的更严度量。**换宽松口径能让数好看，所以不用它。**

## 5. 主流程：一条请求的生命周期

图定义在 `src/kee/qa/graph.py:429-436`，顺序是：

```
START → ①敏感闸 → ②追问改写 → ③混合检索 → ④检索闸 → ⑤生成 → ⑥引用强制 → ⑦置信度与路由 → END
          │                        │                        │              │
          └── 转人工 END            └── 拒答 END             └─ 契约不合格 END└─ 低置信→初步判断/转人工
```

每一档"为什么必须在这、挡住的是哪个业务失败模式、代价是多少"：

| # | 节点 | 挡住的失败模式（业务侧） | 实测代价 / 关键口径 |
|---|---|---|---|
| ① | `sensitive_gate` | 涉密级 3 或敏感问题被自动答出去 ⇒ 合规事故 | 不查关键词表，**按密级规则**判定；命中即转人工，不进检索 |
| ② | `rewrite` | 多轮里"那个的阈值是多少"检不到东西 ⇒ 追问体验直接崩 | 单次 P95 **843ms**，会吃满 800ms 检索预算 ⇒ **默认只在追问轮启用**；改写只服务召回，**重排一律用原查询打分**（否则改得越激进越带偏） |
| ③ | `retrieve` | 检不到 / 检错行业 / 检到没权限看的 | BGE-M3 稠密 + Milvus 服务端 BM25(jieba) + **RRF(k=60)** + BGE-reranker；**RBAC 过滤表达式在这里进 Milvus**（不是事后裁剪）；P95 检索 **302.8ms**（门禁 ≤800ms） |
| ④ | `retrieval_gate` | 证据勉强过线时模型逐字搬运 ⇒ 看起来对、其实没依据 | 阈值 `top_score ≥ 0.20`；不过 → `refuse`，**结论必须为空**（空结论不得判成功） |
| ⑤ | `generate` | 自由文本无法稳定核对出处 | JSON mode 输出「结论 + 要点 + 引用编号」；生成预算 256 token（砍到 96 才能满足 <3s，但那会牺牲答案完整性 ⇒ 口径改 6s） |
| ⑥ | `enforce` | 编造引用 | 逐条要点核对出处，**核对不上的丢掉要点而不是保留文字**；一条不留 → 走"无出处不出结论" |
| ⑦ | `confidence` + 路由 | 把规则分当概率、低质答案当正式结论 | 复合分 = 0.45·检索 + 0.35·引用一致 + 0.20·自评（**规则分，非概率**）；`<0.45` 转人工；分档 `answer / tentative / refuse / escalate / degraded` |

**主流程的三条不变式**（这三条比任何单个节点都更能定义这个项目）：

1. **无来源不出结论**——出处不是附加信息，是答案的准入门槛。
2. **不确定就说不确定**——拒答与转人工是一等出口，不是失败；所以**拒答轮也必须带 `score_basis`**
   （曾经只有作答轮带，于是拒答给下游的是"0 分但没有一句说明这个 0 是什么"，比 0.79 更容易被读成概率）。
3. **权限在检索层强制**——前端看不见、读不到，而不是"读到了被遮住"。

**流式契约**（`retrieval → delta* → answer`）：中间 delta 段是**未经引用强制校验**的 provisional 内容，
前端必须以未完成态渲染、以 `answer` 事件为准。首 token 口径钉死为 **`first_visible_ms`（首个可读字）**，
不是信封首字节——那个数只是 `{`，屏幕上什么都没有。实测 p50 695.4 / p95 859.2ms（门禁 1.2s）。

## 6. 推演被实测推翻的六处（这部分最该保留）

一条链能推出来，不代表它站得住。本项目有六处是**推演合理、跑起来发现错了**：

| 推演时的假设 | 实测结论 | 后果 |
|---|---|---|
| 「端到端 < 3s 是合理目标」（行业 RAG 常见口径） | 256 token 完整答案档 p95 **4118.8ms**，90% 时间在生成段，砍无可砍 | 按三件套改需求原文：门禁 `P95 < 6s 且只统计作答轮次`，含拒答口径 max 7854.6ms 另并报 |
| 「上传 → 准入审核 → 落库」里"准入审核"是一件事 | 实现里只存在**机械准入**（格式/重复/来源分级）；人工复核原本只是事后撤销，未复核内容**当场就能被引用作答**（真 HTTP 实测复现） | 拆成两件事 + 复核章打在**版本**上（章若在文档上，一次复核自动放行以后所有版本——那正是投毒的形状）；闸落在**答案层**：未复核仍可检索（复核人必须看得见才能复核），但不进答案 |
| 「界面上放个角色下拉框，方便演示 RBAC」 | 任何人都能把自己从"新人"切成"系统管理员" ⇒ **RBAC 只在服务端成立** | 撤掉下拉框，换成真登录 + 服务端可撤销会话；请求头身份降为兜底通道并**默认关闭** |
| 「审计表加了 `BEFORE DELETE OR UPDATE` 触发器 = 防篡改」 | PostgreSQL 触发器**不覆盖 TRUNCATE**，且应用角色是超级用户 ⇒ 一句 TRUNCATE 抹干净且不留痕 | 换属主 + 应用改用非特权角色；顺带发现**原方案第②步在 PG 里根本不可执行**（bootstrap 超级用户不许摘 SUPERUSER），只能换路径达成 |
| 「分数从 0.9937 变成 36.9408 是稠密腿空造成的」 | 单腿只要重排跑成就会把分覆盖回 0–1 ⇒ 换量纲要求**重排腿同时被绕过**；而"degraded 是空的"实际是**产物里从来没有这一列** | 主闸门改成分数落域检查（>1 判废、拒绝出读数），补标记只作辅助；探针产物新增 `retrieval_degraded` 列 |
| 「工单有『已填过就拒绝覆盖』护栏，所以重跑生成脚本是安全的」 | 护栏用裸 `csv.DictReader` 读带 `#` 注释头的工单 ⇒ 注释被当表头 ⇒ **已填行数恒为 0** ⇒ 护栏在真人填过的表上也放行覆盖 | 我因此覆盖过一次 12 行真人判断，靠事先记 md5 + `git checkout` 还原；修法 + 8 条回归测试（含"拿真工单验护栏看得见"） |

> 这六处有个共同形状：**它们都不报错**。护栏瞎了不报错、TRUNCATE 缝不报错、单腿退化不报错、
> 假权限入口不报错。所以本项目的纪律是——**凡口径要落成代码闸门，凡闸门要有反面对照测试**，
> 否则它只是文档里的一句话。

## 7. 每条业务诉求现在值多少

| 诉求 | 门禁 / 目标 | 本地实测读数 | 状态 |
|---|---|---|---|
| 检得准（可溯源的前提） | Hit@5 ≥0.95、Recall@5(strict) ≥0.85、MRR ≥0.75、P95 检索 ≤800ms | **0.9853 / 0.9779 / 0.9375 / 302.8ms**（n=68 计分题） | 达标 |
| 出处可信 | 引用落 gold 率 ≥90%（机械可复算） | **0.9839** | 达标（但它是**下限**，见下） |
| 答案对不对 | 不设门禁（只能真人判、不可复跑） | 答案正确率（人判）**0.9677**，n=62、负类仅 2 例 | 报告值；对外必须**同屏给人判这一列** |
| 幻觉率 ≤10% | — | **不适用**（分母为 0：系统在非作答题上一律没给过结论） | 仍是代理读数，**没被改小** |
| 校准 | ECE ≤0.10（报告值） | **0.2006**，方向欠置信；7 行错行按层归因后**没有一行是校准能救的** | 不达标 |
| 快（现场取数小时级→分钟级） | P95 端到端 <6s（仅作答轮次）、首可见 <1.2s | **4118.8ms**、**859.2ms**；含拒答 max 7854.6ms、4% 超 6s | 达标（口径见 V1.21） |
| 可隔离 + 可审计 | RBAC 检索层强制、审计不可篡改 | DoD#7 部分达标；TRUNCATE 缝已堵、身份只认令牌 | 部分达标 |
| 自助解答率 ≥60% | 业务指标 | **模拟**自助解答率 0.9265（84 任务 / 走生产 HTTP） | 部分达标——**测试用户只替代"操作者是人"这一维** |
| 重复提问下降 ≥30%、新人上手缩短 ≥30% | 业务指标 | 缺上线前基线 / 缺真人时间维度 | **按构造不可测**，不是"还没测" |

DoD 汇总：**达标 3 / 部分达标 4 / 不达标 0 / 本次产出 1**。
"部分达标"四格全部因为**同一件事**：那个数字要么只能真人判、要么缺基线，不是实现没做。

## 8. 边界：不做什么，以及留着哪些口子

**明确不做**（第七节 Won't）：对外多租户 SaaS、代替人做决策、自训/微调基础模型、原生 App、
超长上下文硬扛、自建基础大模型。**用 RAG 分块替代堆上下文**这条尤其重要——它是"可溯源"的另一面：
上下文堆到 32k 也能"看起来答对"，但出处就没了。

**当前留着的口子**（风险登记册 11 条敞口，摘要）：
- 撞库侧：`failed_count` 只计数，**不锁号也不限速**；账号无删除端点；口令无轮换策略。
- 引导侧：库里为空时**首个注册者可以是治理角色** ⇒ 首次注册必须受控网络内先到先得。
- 复核侧：复核是**事后闸**，上传到复核完那段窗口里，投毒内容在检索结果中可见。
- 数据侧：ECE 要更多**有方差的负例**（人力活）；真幻觉率要"非作答题上系统真给出过结论"的样本。
- 迁移侧：接企业统一身份（OIDC/LDAP/网关 JWT）时 `app_user` 怎么迁**未设计**（用户裁"留"）。
- 已按证据决定**不修**并留账的两条：q-044 的检索缺口（唯一有效配置只剩 40ms 门禁余量 < 噪声地板 93.6ms）、
  索引侧书面语别名（上界探针净收益 **−1**）。
