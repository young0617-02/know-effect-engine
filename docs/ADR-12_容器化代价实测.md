# ADR-12 决策材料：API 进容器的代价，第一次量出来

> 状态：**仍待裁决**。这份材料只补数，不做决定。
> 此前反对容器化的一方（包括我自己写在 `docker-compose.m4.yml` 注释里的话）说的都是
> 「要拉 GB 级轮子 / 再要一份 CUDA 运行时」——**没人量过代价的另一头**：
> 就算不装 GPU 版，CPU 路径下 `P95 检索 < 800ms` 这条门禁还成不成立。
> 那句话没有数，就不该当论据用。本轮把它量了。

## 一、实测怎么做的（零下载、可复跑）

`scripts/m4_cpu_path_probe.py`：本机 CUDA 环境里**同一套权重**强制换 `device`，跑同一份工作，三种配置对照。

这不是"模拟容器"，是**容器里唯一可行路径的下界**——容器还要多付一层宿主↔容器的网络与 gRPC，只会更慢。

| 配置 | 单条查询嵌入 | 重排 20 候选 | 合成一次检索（嵌入+重排） | 装载 embed / rerank |
|---|---|---|---|---|
| `cuda` + fp16（现状） | 32.0ms | 146.2ms | **178.1ms**（最差 200.3ms） | 14097ms / 5387ms |
| `cpu` + fp16 | 179.3ms | 25974.4ms | **26153.7ms**（最差 26697.3ms） | 3731ms / 5245ms |
| `cpu` + float32 | 96.4ms | 5070.5ms | **5166.9ms**（最差 5224.4ms） | 2839ms / 5355ms |

对照基线：`m2_eval` 的 P95 检索 **326.4ms**（GPU 全链路，含 Milvus 侧 BM25、RRF、网络）。
上表 178.1ms 是"嵌入+重排"两段的合成，量纲比基线小，所以两者不冲突——**别把它们当同一个数引用**。

## 二、三条结论

1. **CPU 路径打不过检索门禁**。最好的一档（CPU+float32）合成 **5167ms**，
   是 800ms 阈值的 **6.5 倍**；fp16 那档更是 33 倍。
   ⇒ 「容器化但只装 CPU torch」不是"慢一点"，是**把 ② 的量化门禁从达标变成不可达**。
2. **CPU 上 fp16 是负优化**：25974ms vs float32 的 5070ms，慢 5.1 倍
   （CPU 对半精度是软件模拟）。⇒ 真要容器化，除了换设备还得改 `KEE_MODEL_DTYPE=float32`，
   这本身又是一处"容器配置与宿主配置不同"的分裂，版本锁定清单要跟着改。
3. **本地没有任何 GPU 基础镜像**（`docker images` 全表里无 `cuda`）。
   所以容器化必须拉 `nvidia/cuda` 系基础镜像（GB 级）——
   这条**直接顶在本机的硬约束上**：不下载 GB 级大件、大件复用本机既有资产。

## 三、三条路的代价，摊开写

| 路 | 做什么 | 代价（实测/可核） | 换来什么 |
|---|---|---|---|
| **① 维持现状**（API 在宿主，仅存储+前端进容器） | 不动 | 零下载零改动；但「断网下端到端问答」测不了（`internal: true` 一切宿主通路就断，已实测），这是一句**永远说不出口**的话 | 保住 P95 检索 326ms 与 800ms 门禁 |
| **② 容器化 + GPU**（`nvidia/cuda` 基础镜像 + GPU runtime） | 拉 GB 级基础镜像、容器内再装一份 torch | **违反本机不下载大件的约束**；且 Docker Desktop 的 GPU 直通在本机未验过 | 拓扑与方案一致；能真正测「整机断网跑通问答」 |
| **③ 容器化 + CPU torch** | 拉 CPU 轮子（~200MB 量级） | 检索合成 **5167ms**（float32 最优档）→ **② 的检索门禁不可达**；dtype 还要与宿主分叉 | 拓扑一致，但**用一条量化门禁换拓扑好看** |

**我的建议是 ①，并把"断网下端到端"明确降级为"本项目不承诺"**：
这条能力对外的真实价值是「客户内网可离线部署」，而 ⑥ 已经用三条结构性证据支撑了数据不出域
（容器封公网 + 仅绑定回环 + 宿主连接审计 0 出网 + 云端兜底 `false`），
③ 是用**已达标**的检索门禁去换一句更好听的话，②是把硬约束顶掉。
若你要的是"对外可复制部署"，那更该在 MVP 之后另开一轮用**部署清单 + 一键脚本**解决，而不是把应用塞进容器再自废门禁。

## 四、如果选 ①，必须同时做的三件事（不然就是"回避"而不是"决定"）

1. 在《项目定义》第十节/第八节把「单机 Docker Compose 全组件本地化」的适用范围**写明**：
   存储与前端进容器，**API 按设计跑在宿主**，并给出理由与代价。
2. 把「断网下端到端问答」**从验证清单里划掉**并注明不可测的原因，不是留在原地当"待办"。
3. `ADR-12` 从「待裁决」改「已定（接受偏离）」，版本锁定清单里 API 依赖另列一份宿主环境要求。

证据：`var/gate0/m4_cpu_path.json`。相关既有实测：`var/gate0/m4_airgap_nodev.json`
（`enable_ip_masquerade=false` 在 Docker Desktop 上切不掉容器出网的负结果）。
