# 前端流式渲染契约（M4）

> **这份文档管什么**：`POST /api/v1/answers/stream` 的事件到浏览器之后**必须怎么渲染**，
> 以及每条要求在哪一段代码里被钉住。它不是实现说明，是**可断言的规格**——
> 凡是这里写了「必须」的，都在 `frontend/src/pages/AskPage.test.tsx` 或 `scripts/verify_m4.py` 里有对应断言；
> 没有断言的条款会当场标成「未验证」，不混在达标项里。
>
> **口径来源**：方案 V1.0.7 的流式契约（§7.2 端点表 + 修订记录）、`reports/m4/M4_流式交付实测.md`。
> M3 报告 §六 里「阶段级 / 与 JSON 互斥 / 待裁决」那段已被 V1.0.7 作废，**不要照那节实现**。

---

## 一、事件序列与状态机

```
retrieval → delta* → answer          （正常）
retrieval → delta* → error           （异常收尾）
```

| 条款 | 内容 | 钉在哪 |
|---|---|---|
| C-1 | `answer` **恰好一次，且是最后一个事件** | `verify_m4.py` 分帧计数 + `kee/api/app.py` 只在落库后 yield |
| C-2 | 流里没等到 `answer` 就结束了 → 界面**必须报错**，不得留在「生成中」 | `AskPage.test.tsx`「流结束了却没有 answer」 |
| C-3 | 依赖不可用时后端在**建流之前**返回 503 + 契约错误体，前端走错误路径 | `sse.test.ts`「依赖挂了要在建流之前抛出契约错误」 |

## 二、三态（这份契约的核心）

`delta` 段是 `conclusion` / `key_points` 的文字，它们**必然早于引用强制校验**：
JSON 模式下结论排在信封最前，而校验要等整段解析完——这是次序使然，不是实现缺陷。
所以界面上「流出的文字」和「成立的答案」必须是两个不同的视觉状态，谁都不能冒充谁。

| 态 | 触发 | CSS 类（必须与另两态不同） | 断言 |
|---|---|---|---|
| 未完成 | `delta` 携带 `provisional: true` | `kee-state--provisional` | 类名存在性 + C-4 |
| 已确认 | `answer` 事件的非空 `conclusion` | `kee-state--confirmed` | `AskPage.test.tsx` 第 1 条 |
| 已撤回 | `answer` 曾流过文字但最终没成为答案（`provisional_retracted` 或结论为空） | `kee-state--retracted` | 第 2 条 |

| 条款 | 内容 | 钉在哪 |
|---|---|---|
| C-4 | **撤回不得静默删除**：流出去的文字要以已撤回态留在页面上，并附「流出 N 字未成为对外答案」的说明 | 第 2 条断言原文与说明文字 |
| C-5 | `delta.text` 是**该槽位的累计内容**（后端按 `(field,index)` 去重后发出），前端整段替换、不做拼接 | 第 1 条断言 `not.toContain("2oo32oo3")` |
| C-6 | 结束后不得残留未完成态样式 | 第 1 条断言 `.kee-state--provisional` 为 null |

> 类名是契约的一部分，不是实现细节：它们集中在 `frontend/src/styles.ts`，
> 组件与测试共用同一组 token，改名会同时打断两边而不是只让测试悄悄变绿。

## 三、答案区域必须出现的五项

方案要求流式渲染「结论 + 要点 + 引用 + 置信度 + 免责提示」，逐项落点：

1. **结论**：`[data-slot=conclusion]`，三态之一。`refuse` 时显示「本轮没有可给出的结论」而**不是空白的**。
2. **要点**：`answer.key_points[]`，每条带 `[E1]` 形式的出处锚点；`dropped_points`（被引用强制丢掉的）要显式列出丢了几条。
3. **引用**：`answer.citations[]` 渲染 `doc_id / 章节 / 页码 / 密级`；**片段正文不来自 answer**，
   而来自 `POST /api/v1/chunks/batch`（见第五节）。
4. **置信度**：显示 `composite`、`calibrated`、`temperature`，并**原样带出 `score_basis=rule_composite_not_probability`**。
   禁止渲染成「置信度 78%」这类概率口径（M3-04c 已把它降为规则分）。
5. **免责提示**：一句固定文案，声明内容由本地模型生成、引用可逐条核对、置信度不是概率。

| 条款 | 内容 | 钉在哪 |
|---|---|---|
| C-7 | 置信度不得以概率口径呈现 | 第 3 条断言（含 `not.toMatch(/置信度\s*78%/)`） |
| C-8 | `needs_human` 必须可见（徽标），拒答/转人工不得伪装成正常答案 | 第 4 条断言 |

## 四、多轮与会话

- `answer` 事件带 `session_id` 与 `turn_no`；前端存下 `session_id` 供追问复用，`turn_no` 用于展示轮次。
- 会话历史只从 `GET /api/v1/sessions/{id}` 读（权威源是 PG 的 `session_turn`，LangGraph 不接 Checkpointer）。
- **追问才开 `rewrite`**：首轮字面查询自足，多花一次模型调用不划算（实测单次改写 P95 843ms）。
  界面上这条开关要带着耗时标注，让人知道它在花什么。
- **一问一答（V1.31 起的版式契约）**：一轮 = `.kee-turn` 里**恰好一条** `.kee-turn__question`（问题气泡）
  + **一条** `.kee-turn__answer`（答案气泡）。追问**不覆盖前答**，历史在同一列里累积。
  钉在 `AskPage.test.tsx`「一问一答的版式」那组：DOM 顺序（正文在前、输入栏 `.kee-ask-dock` 在后）
  与「两问之后仍是 2 个成对节点」都有断言。
- **只有正文区滚动，整页不滚**：`.kee-shell` 撑满一屏（`100dvh` 的 flex 列），
  `.kee-turns` 是唯一滚动容器（`overflow-y:auto` + `min-height:0`——不写 `min-height:0` 时
  flex 子项按内容撑高，滚动会顶回外层，表现就是"输入框被推走"）。
- **跟随策略不许和用户抢滚动条**：流式每帧都刷新视口会把用户往上翻的历史顶回去，
  所以「贴底才跟随」（距底 < 40px 视为贴底；发新问题时强制回到底）。
  实测：流式中上翻 739px，收尾仍在 739px；翻回底部后下一轮收尾距底 39px（恢复跟随）。

## 五、身份与读取范围（RBAC 的界面兑现）

- **身份主通道是登录令牌**（V1.31 起）：`Authorization: Bearer <token>`，由 `POST /api/v1/auth/login` 签发。
  有令牌时角色、行业、项目与审计 actor **全部取服务端账号**，请求头不参与判定。
  令牌存在 `localStorage`（键 `kee.token`，代码里导出为 `TOKEN_KEY`，测试引用同一个常量——
  这个键一度被写成占位符 `"***"`，读写同一个错键所以自洽地全绿，直到「会话过期要清令牌」那条测试照出来）。
- **请求头是兜底通道**：`X-Kee-Role / X-Kee-Actor / X-Kee-Industries / X-Kee-Projects`，仅在无令牌时生效，
  且可被服务端 `KEE_ALLOW_HEADER_IDENTITY=false` 整体关闭。
  **头里只能是 latin-1 字节**，所以中文取值（行业名「金融」、含 `@` 的 actor）两端都做百分号编码：
  前端 `identityHeaders` 用 `encodeURIComponent`，后端 `context_of` 用 `unquote`。
  这条不是风格问题——直接发中文，浏览器会拒发整个请求（`sse.test.ts` 里有断言）。
- **强制点在检索层**：`security_level / industry / project` 收敛进 Milvus 过滤表达式；
  前端的角色表只用于呈现可选项，**不做任何判定**。越权的表现是「搜不到 / 读不到正文」，不是「前端藏起来」。
- `POST /api/v1/chunks/batch` 与检索层同口径过滤，且**只返回生效版本**的正文；
  越权与不存在的 id 合并进 `hidden`，不告诉调用者属于哪一类（那本身就是信息泄露）。
- **界面上没有角色选择器了**（V1.31）：旧版那个下拉框任何人都能把自己从「新人」切成「系统管理员」，
  使「RBAC 已实现」只在服务端成立。现在未登录只有登录/注册页，登录后账号条**只读**显示
  服务端给的可见密级与过滤表达式——它陈述的还是那件与渲染有关的事实：
  **过滤发生在检索层，不是前端把结果遮住**。
  「请求头身份可伪造」这条约束仍不在界面上（用户 2026-10-13 令：保持界面干净），
  它留在《技术方案》7.2.1、《版本锁定清单》与风险登记册；⚠ 但**默认值仍是 `true`**，
  也就是这条约束目前由部署环境承担，翻不翻是待用户拍的一条。

## 六、明确不在本契约里的东西（防止读错）

1. **① 的「流式首 token < 1.2s」口径已于 V1.0.23 / V1.21 定案**：门禁取 `first_visible_ms`（首个可读字），
   本契约文档初版那句「实测 2307ms ⇒ 未达标」用的是**信封首字节**那一档的旧读数，已不作达标依据。
   现在的读数是热态 307ms（`verify_m4` 把冷热分开，冷装载单列）。
2. `token_stream` 的默认值（当前 `true`）仍是待裁决项，不是已定口径。
3. 条目级丢失（`provisional_lost`）当前读数为 0，那是本语料的性质，不是设计保证。
4. **像素/几何级验证（V1.31 起已做）**：Qoder 的 in-app 浏览器拿不到可见视口（`innerHeight=0`，
   在它上面量的任何布局数字都是 0×0 视口里的假象——本轮先踩过一次），
   改用 Playwright CLI + 本机 Edge 在 **1440×900 真视口**下量几何并截图核对：
   整页不滚（`docScrollH=900=innerHeight`）、正文区自滚（视口 503px / 内容 1656px）、
   输入栏顶边 784 == 正文底边、6 轮各 1 问 1 答、上翻不被拽回。

```bash
cd frontend && npm run test          # 29 条：SSE 分帧 + 三态渲染 + 读取范围 + 登录闸门 + 一问一答版式
uv run python scripts/verify_m4.py   # 端到端：事件顺序、answer 恰好一次、经 Nginx 的 SSE 不被缓冲
```
