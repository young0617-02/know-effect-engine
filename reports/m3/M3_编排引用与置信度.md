## 一、M3-00 编排框架选型落地：LangGraph 装上去了，且没动到底座

方案技术主线与 6.3 指定 **LangGraph StateGraph**（确定性编排 + Checkpointer 多轮）。
但本 venv 的 torch/transformers 是由 `scripts/bootstrap_env.py` 写 `.pth` 挂载
`D:\py312-torch` 提供的，而 `langchain-core` 自带 pydantic 版本约束——**先验证再依赖**，
没有直接开写状态机。

### 验证方法

装前 `pip freeze` 存档 → `--dry-run` 看解析结果 → 实装 → 再 freeze 做**逐行 diff** →
复验关键底座与全量单测。

### 结果：依赖树只有「新增」，没有「升级」与「卸载」

`diff` 输出 21 行全部是 `>`（新增），**`<`（被改动/移除）为 0 行**：

```
langgraph==1.2.14          langgraph-checkpoint==4.2.0     langgraph-prebuilt==1.1.0
langgraph-sdk==0.4.6       langchain-core==1.6.9           langchain-protocol==0.0.19
langsmith==0.14.7          jsonpatch/jsonpointer           ormsgpack  tenacity  sniffio
distro  httpcore2  httpx2  requests-toolbelt  truststore  uuid-utils  websockets
xxhash  zstandard          langgraph-checkpoint-postgres==3.1.2  psycopg-pool==3.3.3
```

关键底座**版本一字未动**：

| 包 | 装前 | 装后 |
|---|---|---|
| pydantic | 2.14.0 | 2.14.0 |
| fastapi | 0.143.0 | 0.143.0 |
| starlette | 1.7.0 | 1.7.0 |
| anyio | 4.15.1 | 4.15.1 |

| numpy | 2.5.3 | 2.5.3 |
| **torch** | **2.14.0+cu130** | **2.14.0+cu130，`cuda.is_available()=True`** |

复验：`langgraph.graph.StateGraph` 编译并 `compile()` 成功；`PostgresSaver` 可导入；
`kee.qa.answer` 与 `kee.api.app` 导入正常；**84 项单测全绿**。

### 一个值得记的细节

`langchain-core` 依赖的是 **`httpx2`**（与本项目用的 `httpx 0.28.1` 并存、互不覆盖）。
这与之前 `starlette.testclient` 那条「install httpx2 instead」的弃用告警对得上——
也就是说这条依赖链不会把我们的 httpx 顶掉，Ollama 客户端不受影响。

### 多轮状态的存放选择

采 `langgraph-checkpoint-postgres`（+`psycopg-pool`，共 2 个新包、无升级），而不是 Redis 或内存档：
**PostgreSQL 是本项目唯一权威源**（方案 7.1 / V1.1 第十节），会话与轮次状态放 PG 与
「其余存储皆可丢」的口径一致；Redis 侧只承担可丢弃的运行态缓存。

### 结论

M3 可以按方案原定形态推进（LangGraph 类型化状态机 + PG Checkpointer），**不需要走 3.4 回退分支**，
也不需要记方案偏差。Gate 0 ① 建立的 8GB 显存调度基线未被这次安装触及。
