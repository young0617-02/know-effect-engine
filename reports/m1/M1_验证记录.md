## 三、这一版实际建成的能力

- **多格式解析适配层**：Markdown（front-matter + H 层级 + 表格展平）、TXT（编号行启发）、DOCX（Heading/Title 样式 + 表格展平）、PDF（pypdf 逐页抽取，真实页码）。所有解析器统一吃字节流，不落临时文件——Windows 下 python-docx/pypdf 持句柄会让临时件删不掉。
- **元数据三级取值**：表单 > 文档 front-matter > 推断，每一级来源都产生 `meta_warnings` 并写入审计；缺 `customer/project` 时落占位并**显式告警**，不静默放宽隔离域。
- **版本管理**：`bump_version` 保证任一时刻每文档只有一个 effective 版本，并在摄取时撤下旧版本索引；`rollback` 用权威源 + 物料仓重建目标版本。
- **对内 REST API**：`/api/v1/documents/upload|{id}|review|rollback`、`/api/v1/retrieval/search`、`/api/v1/reconcile/run`、`/healthz`；统一错误码 E4xx/E5xx/E9xx + `trace_id` + `retryable`；写操作支持 `Idempotency-Key`。
- **合规机制**：RBAC 在检索层过滤（表达式对 `security_level/industry/project` 收敛）；职责分离落到「上传者不能自审」；审计表 UPDATE/DELETE 被触发器拒。
- **对账作业**：CLI 与 HTTP 两条入口，同一套 diff/repair 实现；`--dry-run` + 退出码 2 供编排告警。

## 四、已知限制（不得当作已完成）

1. **MinerU 未接入**。本机只有 `MinerU-4_models_onnx` 权重、没有 mineru 包，且本轮约定不下载 GB 级依赖。后果：扫描件/图片页 PDF 抽不出文字；表格只做按行展平，不保留版面结构；无版面标题时章节退化为单章节。适配层已留 `PARSERS` 注册位，接入 MinerU 不需要改链路。
2. **PDF 页码粒度**：`chunk.page` 取所属章节起始页。上例真实 PDF 未被识别出章节，其全部子块落在第 1 页。引用"可定位到页"在章节可识别时成立，在扫描件/无编号版面上不成立。
3. **分块 ID 命名已修正但不一致**：修 `chunk_document` 的双前缀缺陷（`doc@doc@v1#…` → `doc@v1#…`）之前建的 193 个 Gate 0 分块仍是旧命名，新摄取文档用新命名。下次全量重建（`g02`）统一；当前索引里没有混名的文档。
4. **鉴权是占位**：角色/身份来自请求头（`X-Kee-Role`/`X-Kee-Actor`），没有真登录、令牌与用户目录。职责分离因此可被伪造 header 绕过——内网 Demo 可接受，生产必须换真实身份源。
5. **未做**：Neo4j 图谱、增量级分块复用（同文档小改目前全文重切）、xlsx 解析、多集合分域对账（对账口径仍是"一份权威源 ↔ 一个索引"）、查询改写与多轮追问、答案复核闭环。
6. **文档内容里的外部 URL 会被原样入库**（真实 PDF 中含厂商服务网址）。这不构成出域（不发生任何外部调用，Gate 0 ⑥ 已验），但答案层若直接复述链接需要在 M3 的引用校验里加一条链接治理。
