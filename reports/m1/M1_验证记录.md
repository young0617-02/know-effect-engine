## 三、这一版实际建成的能力

- **多格式解析适配层**：Markdown（front-matter + H 层级 + 表格展平）、TXT（编号行启发）、DOCX（Heading/Title 样式 + 表格展平）、PDF（pypdf 逐页抽取，真实页码）。所有解析器统一吃字节流，不落临时文件——Windows 下 python-docx/pypdf 持句柄会让临时件删不掉。
- **元数据三级取值**：表单 > 文档 front-matter > 推断，每一级来源都产生 `meta_warnings` 并写入审计；缺 `customer/project` 时落占位并**显式告警**，不静默放宽隔离域。
- **版本管理**：`bump_version` 保证任一时刻每文档只有一个 effective 版本，并在摄取时撤下旧版本索引；`rollback` 用权威源 + 物料仓重建目标版本。
- **对内 REST API**：`/api/v1/documents/upload|{id}|review|rollback`、`/api/v1/retrieval/search`、`/api/v1/reconcile/run`、`/healthz`；统一错误码 E4xx/E5xx/E9xx + `trace_id` + `retryable`；写操作支持 `Idempotency-Key`。
- **合规机制**：RBAC 在检索层过滤（表达式对 `security_level/industry/project` 收敛）；职责分离落到「上传者不能自审」；审计表 UPDATE/DELETE 被触发器拒。
- **对账作业**：CLI 与 HTTP 两条入口，同一套 diff/repair 实现；`--dry-run` + 退出码 2 供编排告警。

## 四、已知限制（不得当作已完成）

1. **MinerU 以「本地 ONNX 自建后端」接入，不是 mineru 包**。本机 `D:\modelscope\hub\models\MinerU-4_models_onnx`（819MB：PP-DocLayoutV2 / PP-FormulaNet-M / PP-OCRv6 det+rec / SLANet-plus / UniNet）由 onnxruntime(CPU) + pypdfium2 驱动，零大件下载、零外网调用。不 `pip install mineru` 的理由：包本身 3.5MB，但依赖树带 lmdeploy / gradio / mineru-llama-cpp / accelerate，与本 venv 经 `.pth` 挂载的 CUDA torch 底座同装极易互顶版本——为省一点编码量把 Gate 0 ① 已验证的显存基线搞坏不划算。**mineru.net 云端 API 明确不用**（同机另一项目的用法），那属于数据出域，与 V1.1 第八节和 Gate 0 ⑥ 冲突。
2. **已接能力**：整页 det 行框 → 逐行 rec → PP-DocLayoutV2 版面归属 → 章节/正文/表格块结构 + 逐页真实页码。扫描件与无文本层 PDF 从"不可入库"变成"可入库可检索"（18.4s/页）。
3. **未接能力（诚实记账）**：公式识别（PP-FormulaNet-M 模型在本地未接，交付文档公式罕见）；**表格行列结构**（SLANet-plus / UniNet 在本地未接，表格目前按版面框裁出后 OCR 成文本行，行列关系丢失）；**多栏版面串行**——实测丢弃 3 个"有标题无正文"块，双栏页版面归属会错位；OCR 仍有字符级错认（如"和安全"认成"不和以告"），M2 需用 rec 置信度阈值或换 larger rec 模型改善。
4. **架构教训（值得记）**：最初我把**版面块**直接喂给 rec 模型，产出一串看着像中文的乱码——PP-OCR 的 rec 是单行模型。正确链路是 det 出行框、逐行 rec、再用版面框决定归属。这个错在真机上跑一遍才暴露，纯代码审查看不出。
5. **PDF 页码粒度**：`chunk.page` 取所属章节起始页；pypdf 路径未识别章节时全部落首页，MinerU-ONNX 路径为逐页真实页码。
6. **分块 ID 命名已修正但不一致**：修 `chunk_document` 双前缀缺陷（`doc@doc@v1#…` → `doc@v1#…`）之前建的 193 个 Gate 0 分块仍是旧命名，新摄取文档用新命名；下次全量重建（`g02`）统一，当前索引内不存在混名文档。
7. **鉴权是占位**：角色/身份来自请求头（`X-Kee-Role`/`X-Kee-Actor`），没有真登录、令牌与用户目录。职责分离因此可被伪造 header 绕过——内网 Demo 可接受，生产必须换真实身份源。
8. **未做**：Neo4j 图谱、增量级分块复用（同文档小改目前全文重切）、xlsx 解析、多集合分域对账（口径仍是"一份权威源 ↔ 一个索引"）、查询改写与多轮追问、答案复核闭环。
9. **文档内容里的外部 URL 会被原样入库**（真实 PDF 中含厂商服务网址）。这不构成出域（不发生任何外部调用，Gate 0 ⑥ 已验），但答案层若直接复述链接需要在 M3 的引用校验里加一条链接治理。
