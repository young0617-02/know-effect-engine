## 三、这一版实际建成的能力

- **多格式解析适配层**：Markdown（front-matter + H 层级 + 表格展平）、TXT（编号行启发）、DOCX（Heading/Title 样式 + 表格展平）、PDF（pypdf 逐页抽取，真实页码）。所有解析器统一吃字节流，不落临时文件——Windows 下 python-docx/pypdf 持句柄会让临时件删不掉。
- **表格行列结构还原（SLANet-plus，本地 ONNX）**：版面框判出 table → 裁图 → 结构模型坐标头 → 逐行单元格框 → 吸附到行列共识边界 → 已 OCR 的文本行**唯一归属**到单元格 → Markdown 表格入库。跨列合并表头也按「quad 落在所有 cell 之外」回收。详见第三节附。
- **元数据三级取值**：表单 > 文档 front-matter > 推断，每一级来源都产生 `meta_warnings` 并写入审计；缺 `customer/project` 时落占位并**显式告警**，不静默放宽隔离域。
- **版本管理**：`bump_version` 保证任一时刻每文档只有一个 effective 版本，并在摄取时撤下旧版本索引；`rollback` 用权威源 + 物料仓重建目标版本。
- **对内 REST API**：`/api/v1/documents/upload|{id}|review|rollback`、`/api/v1/retrieval/search`、`/api/v1/reconcile/run`、`/healthz`；统一错误码 E4xx/E5xx/E9xx + `trace_id` + `retryable`；写操作支持 `Idempotency-Key`。
- **合规机制**：RBAC 在检索层过滤（表达式对 `security_level/industry/project` 收敛）；职责分离落到「上传者不能自审」；审计表 UPDATE/DELETE 被触发器拒。
- **对账作业**：CLI 与 HTTP 两条入口，同一套 diff/repair 实现；`--dry-run` + 退出码 2 供编排告警。

### 三附：表格结构还原（SLANet-plus）怎么定标、验到什么程度

**前提：本机 `Table/` 目录只有 3 个 onnx，没有随附的 50 词 HTML 词表**，所以 SLANet 输出的 token id
没有任何官方语义可查。不猜标签，改从**坐标头**反推（`scripts/probe_slanet.py`，可复跑，退出码即判定）：

| 探针 | 实测 | 结论 |
|---|---|---|
| A 逐 token quad | 155 token，id 分布 `{48:113, 5:17, 6:17, 其余 7 个各 1}`；id=48 的 113 个 quad 并集覆盖 `x[2,561] y[2,569]`，图像本身 564×571 | id=48 铺满整表 → **单元格**；其余 id 只在首尾出现一次 → 结构标记 |
| B 行列数稳定性 | 按 id∈{5,6} 行终止符切 → **17 行**，每行 cell 数 `[1,7,7,…,7]`；y 中心聚类 thr=0.005/0.01/0.02 均 **17 组**；x 左边界聚类 thr=0.02/0.03/0.05 均 **7 组** | **17 行 × 7 列**，与人工读图真值一致，且**三档阈值都给同一答案**，不是调出来的 |
| C 合并格回收 | 非 cell token 中只有 2 个 quad 与所有 cell 重叠率 ≤0.15（`box=(161,2,553,29)` 与 `(185,3,443,24)`），IoU 去重后留 1 个 | 该框正是第一行「有害物质」跨 6 列的合并表头 → 按「与所有 cell 几乎不相交」回收有效 |

**多样本验证**（`scripts/verify_table_structure.py`，真值 = 我方写入单元格的文本，可逐格比对）：

| 样本 | 真值行列 | 还原行列 | 逐格内容一致（忽略空格） | 逐格原样全等 |
|---|---|---|---|---|
| 普通三列表（合成） | 6×3 | 6×3 | 18/18 | 15/18 |
| 合并表头七列表（合成） | 6×7 | 6×7 | 37/37 | 37/37 |
| 两列长表（合成） | 8×2 | 8×2 | 16/16 | 16/16 |
| 宽表六列（合成） | 4×6 | 4×6 | 24/24 | 13/24 |
| hak180 有害物质表（真实） | 17×7 | 17×7 | 一致（含合并表头） | 部分 |

判定口径**只看结构与落位**（行列数对 + 无单元格串位），OCR 的空格/字符差异单独报数、不计入判定——
否则是拿识别精度冒充结构能力。4 个合成样本的"原样全等"缺口全部是数字与单位之间的空格漂移
（`1200 台` ↔ `1200台`），无一例内容错到别的格子。

**验证过程暴露并修掉的两个真缺陷**（都不是审代码能发现的）：
1. **单格 quad 会画歪**：宽表首行首格右边界画到 393（该列真值 301）、下边界短一截，"区域"二字被
   挤进隔壁格。改为把每格吸附到「所在行 × 所在列」的**中位共识边界**（`snap_rows_to_grid`），
   信多格共识而不是信单格输出。
2. **逐格查找会重复认领**：原实现每格独立查找行文本，同一行会被相邻两格同时认领，
   一个数字在表里出现两次比丢字更糟。改为 `assign_lines_to_cells` **一次性唯一归属**
   （中心在格内优先、并列取中心最近、都不在则半格距离内兜底）。

**顺带修的两处下游连带问题**：`_clean` 原先把所有软换行折成空格，会把 Markdown 表格压成一行 →
按行首 `|` 豁免；子块切分原先按 280 字窗口硬切，会把表格从行中间切断且丢掉列名 → 表格块按行组切、
**每组自带表头行**，且不再与其他文本共用子块、章节标题独占一行。

> **后续修订（2026-10-10，M2）**：上面这段「每组自带表头行的 Markdown 子块」已被推翻。
> M2 表格检索专项实测：整表一块时单元格级问题 **Top1 命中 gold 率 0.0**，「表头+一行」的残块
> 因行行共享表头而不可区分（Hit@5 0.750），最终改为**行级「列名=值」子块**（Hit@5 0.833），
> 整张表只保留在父块里供答案组装。数据与机制见 `reports/m2/M2_检索评测基线.md` 第七节。
> 保留原文是因为当时「Markdown 子块能通过长度归一化与切分」这一层结论本身没错，
> 错的是把它当成检索最优表示。

## 四、已知限制（不得当作已完成）

1. **MinerU 以「本地 ONNX 自建后端」接入，不是 mineru 包**。本机 `D:\modelscope\hub\models\MinerU-4_models_onnx`（819MB：PP-DocLayoutV2 / PP-FormulaNet-M / PP-OCRv6 det+rec / SLANet-plus / UniNet）由 onnxruntime(CPU) + pypdfium2 驱动，零大件下载、零外网调用。不 `pip install mineru` 的理由：包本身 3.5MB，但依赖树带 lmdeploy / gradio / mineru-llama-cpp / accelerate，与本 venv 经 `.pth` 挂载的 CUDA torch 底座同装极易互顶版本——为省一点编码量把 Gate 0 ① 已验证的显存基线搞坏不划算。**mineru.net 云端 API 明确不用**（同机另一项目的用法），那属于数据出域，与 V1.1 第八节和 Gate 0 ⑥ 冲突。
2. **已接能力**：整页 det 行框 → 逐行 rec → PP-DocLayoutV2 版面归属 → 章节/正文/表格块结构 + 逐页真实页码；表格进一步走 SLANet-plus 还原行列与合并表头。扫描件与无文本层 PDF 从"不可入库"变成"可入库可检索"（18.4s/页）。
3. **未接能力（诚实记账）**：公式识别（PP-FormulaNet-M 模型在本地未接，交付文档公式罕见）；**多栏版面串行**——实测丢弃 3 个"有标题无正文"块，双栏页版面归属会错位；OCR 仍有字符级错认（如"和安全"认成"不和以告"），M2 需用 rec 置信度阈值或换 larger rec 模型改善。
3b. **表格结构还原的边界**：验证样本是 **4 张合成表 + 1 张真实表**，本机带表格的真实 PDF 只有 hak180 这一份，所以"合并/斜线表头/无框线表格/跨页表格"这些形态**没有实测过**，不能声称通用可用。已知的硬边界：合并格靠"quad 与所有 cell 不相交"这一几何判据回收，只在 hak180 与一张合成表上验证过（各 1 例）；无框线表格 SLANet 本身就没有可依赖的坐标头信号；跨页表格目前逐页独立成表，不做表头续接。
4. **架构教训（值得记）**：最初我把**版面块**直接喂给 rec 模型，产出一串看着像中文的乱码——PP-OCR 的 rec 是单行模型。正确链路是 det 出行框、逐行 rec、再用版面框决定归属。这个错在真机上跑一遍才暴露，纯代码审查看不出。
   第二条同类教训来自表格结构：SLANet 的**序列头**（50 词 HTML）在本机没有词表就是废信息，但**坐标头**是自带的——真正可用的结构信号是 113 个 cell quad，不是 token 标签。反过来，坐标头单格会画歪，所以「信单格输出」要改成「信多格共识」。这两条都是先按直觉写完、被多样本比对才拦下来的。
5. **PDF 页码粒度**：`chunk.page` 取所属章节起始页；pypdf 路径未识别章节时全部落首页，MinerU-ONNX 路径为逐页真实页码。
6. **分块 ID 命名已修正但不一致**：修 `chunk_document` 双前缀缺陷（`doc@doc@v1#…` → `doc@v1#…`）之前建的 193 个 Gate 0 分块仍是旧命名，新摄取文档用新命名；下次全量重建（`g02`）统一，当前索引内不存在混名文档。
7. **鉴权是占位**：角色/身份来自请求头（`X-Kee-Role`/`X-Kee-Actor`），没有真登录、令牌与用户目录。职责分离因此可被伪造 header 绕过——内网 Demo 可接受，生产必须换真实身份源。
8. **未做**：Neo4j 图谱、增量级分块复用（同文档小改目前全文重切）、xlsx 解析、多集合分域对账（口径仍是"一份权威源 ↔ 一个索引"）、查询改写与多轮追问、答案复核闭环。
9. **文档内容里的外部 URL 会被原样入库**（真实 PDF 中含厂商服务网址）。这不构成出域（不发生任何外部调用，Gate 0 ⑥ 已验），但答案层若直接复述链接需要在 M3 的引用校验里加一条链接治理。
