# M1 · 图片、图表与公式解析实测

> 日期：2026-10-26｜范围：入库期 VLM 描述索引 + PP-FormulaNet 公式识别
> 结论先说：**云端 VLM 链路真实跑通**（Modelscope OpenAI 兼容端点，模型 `Qwen/Qwen3.8-27B`），
> 独立图片、DOCX 内嵌图片、文本层 PDF 图表、扫描件 PDF 四条入口均产出了可入库的「OCR 文字 + 中文描述」；
> 公式模型在本机用合成公式 PDF 实测输出 LaTeX，但复杂分式结构仍不完美。
> **本地 Qwen3-VL 未实跑**；云端调用意味着图片与提示词出域，这是用户在 `.env` 中显式配置并放行的。

## 二、实测结果

### 2.1 独立图片（合成季度交付柱状图）

- 入口：`parse_image()` → `MediaPipeline.process_image_bytes()` → 真实 OCR + 云端 VLM。
- OCR：`Quarterly Delivery Amount (10k CNY) Q4: 210 Q3: 180 Q2: 150 Q1: 120`
- VLM 描述：`柱状图，标题“Quarterly Delivery Amount (10k CNY)”。四个蓝色柱，自左至右标注：Q1: 120、Q2: 150、Q3: 180、Q4: 210。无坐标轴刻度与图例，仅底部横线。趋势为逐季递增。`
- 延迟：VLM 4.36s；admission **1/1 通过**；分块文本包含「图内文字」与「内容描述」。

### 2.2 DOCX 内嵌图片（合成月报折线/柱状图）

- 入口：`parse_docx()` 从 `word/media/image1.png` 抽取 → OCR + VLM。
- 新增章节：`图片与图表`。
- OCR：`Monthly Defect Trend 42 31 18 9`
- VLM 描述：`柱状图，标题“Monthly Defect Trend”。无坐标轴标签及图例。四根红色柱形，数值自左至右依次为42、31、18、9，整体呈下降趋势。`
- 延迟：VLM 3.02s；描述与 OCR 进入同一子块。

### 2.3 PDF 图表（合成里程碑柱状图）

- 入口：`parse_pdf()`；该合成 PDF 文本层很薄，实际走 MinerU 版面路径并判出 `chart` 区域。文本层厚的 PDF 由
  pypdf `pdf_images()` 路径覆盖，单测 `test_pdf_images_extraction_returns_paragraphs` 已跑通。
- VLM 描述：`柱状图，无标题、无坐标轴标签及图例。含四个绿色柱，自左至右顶部标签及数值为：Plan 30、Build 80、Test 120、Launch 160。柱高依次递增，呈上升趋势。`
- 延迟：VLM 3.85s；`KEE_VLM_MAX_FIGURES_PER_PAGE=1` 时只调用一次，其余小图跳过。
- **一处质量边界**：页面顶部的 `Project Delivery Milestones` 标题在图表区域之外，VLM 因此说「无标题」——描述只依据裁剪区域 + OCR，不保证覆盖页面级标题。

### 2.4 扫描件 PDF（`var/m1/fixtures/扫描件_产品安全手册第1页.pdf`）

- 入口：MinerU 页面渲染 + 真实版面/OCR + 云端 VLM。
- 版面判出 2 个较大图表区域、5 个小图/超限区域被跳过（保留 OCR 文字）。
- VLM 描述（节选）：`示意图左上角为禁止符号（圆圈加斜杠）。主体为一台桌面打印机/复印机线稿……整体示意禁止此种放置或出纸方式。`
- 延迟：VLM 6.19s；说明扫描页里的图示可被描述索引覆盖，但描述质量依赖版面裁剪。

### 2.5 公式 PDF（本地 PP-FormulaNet_plus-M）

- 入口：MinerU 版面判出 `display_formula`，本地 564MB ONNX 推理，不联网。
- 输入：浏览器 MathML 渲染的二次求根公式。
- 输出（节选）：`\begin{aligned} &\left\{ ... & -b \pm \sqrt{b^2 - 4ac} ... \end{aligned}`
- 结论：公式符号被识别出来，但分式/对齐结构仍不完美；正式使用前需按行业公式集验收。
- 去重：同一公式被版面模型输出 3 个重叠框时，`_dedupe_regions()` 去重为 1 个，避免重复 LaTeX。

## 三、数据流（为什么服务阶段不跑 VLM）

```
入库：文档/图片 → 抽取 → OCR → VLM 描述 → 普通段落
      → Parent-Child 分块 → BGE-M3 嵌入 + BM25 → Milvus

服务：文本 Query → 混合检索 → 纯文本 qwen2.5:7b → 引用/拒答/转人工
```

VLM 只在 `parse_*` 的入库路径调用；`src/kee/qa/` 与 `src/kee/retrieval/` 没有任何 VLM 依赖。

## 四、如实边界

1. **云端数据出域**：本次调用把合成测试图片与提示词发到了 Modelscope；这是 `.env` 显式配置 `KEE_VLM_ALLOW_REMOTE=true` 的结果。生产交付必须换回本地 vLLM 或关闭 VLM。
2. **本地 Qwen3-VL 未实跑**：代码支持 OpenAI 兼容本地端点，但没有在本机启动 8B 视觉模型；8GB 显存下不要与在线 7B/嵌入/重排同时常驻。
3. **图表准确率未做行业评测**：本次只验证了合成柱状图、真实扫描件示意图；未覆盖复杂多轴图、堆叠图、表格截图、跨页图。
4. **公式准确率未验收**：二次求根公式能出 LaTeX，但分式结构不完美；未覆盖矩阵、分段函数、手写公式。
5. **描述不等于原文**：`内容描述` 是模型生成，引用时必须标为图片描述，不能当原文逐字引用。
6. **已有索引不回填**：本次只验证解析路径；开启 VLM 前已入库的文档不会自动长出描述，需要重新摄取。
7. **不保存原图**：只把 OCR 文字和描述写进知识块，答案不能回链到原图。
8. **成本/延迟**：单张图 VLM 约 3–6s（本次实测），一篇 20 图的文档约 1–2 分钟；必须按离线入库作业排期。
