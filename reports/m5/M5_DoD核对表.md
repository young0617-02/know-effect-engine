## 这张表暴露的三处口径冲突：**已全部定案**（第 1、2 条 V1.21 / V1.0.23，第 3 条 V1.22 / V1.0.24）

1. **P95 完整答案 / 端到端**：曾三处两个值（DoD#5 `< 3s`、《项目定义》第六节与本文 8.1 `< 6s`）。**已定案：门禁 = P95 < 6s 且只统计作答轮次**——净环境 4 轮 76 个作答轮次 p95 4118.8ms、0% 超 6s（>3s 是 68.42% ⇒ 3s 那一边在 256 token 完整答案档**不可达**，要达就得改生成预算或换模型，那是实现改动不是措辞改动）。**含拒答轮次仍须另并报**（max 7854.6ms、4% 超 6s）——两条拒答路径成本差 18 倍，这就是它不能与被测对象混进同一个分位数的理由。
2. **首 token 1.2s**：口径已钉死为 **`first_visible_ms`（首个可读字）**。三种读法同轮量齐（n=24）：信封与首事件 p50 324.0ms、首个可读字 p50 695.4 / p95 859.2 / max 1008.6ms ⇒ 按最严那把达标。信封那个数只是 `{`，**不得当达标依据**——这句现在写在门禁文字里，不靠谁记得。
3. **「引用正确率」到底指什么**：**已于 V1.22 / V1.0.24 定案——名字拆成两个，不再共用一个词**。门禁 = **引用落 gold 率 ≥ 90%**（机械可复算，任何人重跑必得同一个数；现值 0.9839）；**答案正确率（真人判 `answer_correct`）= 报告值**（现值 0.9677），附 n=62 与覆盖边界，**不当门禁**。不当门禁的理由要说全：它只能真人判、不可复跑，且 n=62、负类仅 2 例（AUC CI 宽到 0.627–0.914）——薄到撑不起一个门禁。**但对外展示必须同屏给人判那一列**，它是下限的那条不能独占「可信」这个词。此前两数并存却共用一名、都能自称 ≥ 90% 而说的不是同一件事——那才是本条要关的洞。
