## 六、口径与边界（引用这一格必须连着说的话）

- **Context Precision / Recall 用的是检索面（复跑 Top-5），不是被引块**：它们测「检到了没有」，Faithfulness 测「说出来的有没有依据」，分工不同，所以同一题可以 F=1.0 而 CP=0.2，那不是矛盾。CP/CR 覆盖**全 67 行**（含拒答/转人工行）——拒答行的检索面照样要评，「该答却检不到」正是 Context Recall 要暴露的东西。
- **CP 的「一块都不相关」那批行报不适用、不报 0**：位置加权公式的分母是相关块数，5 块全不相关时该式未定义。官方实现把这类样本折成 0.0 计入均值——**两种写法会给出不同的数**，引用时必须说明是哪一种；本装置另报「相关块数为 0 的行数」这个事实，不把它藏进均值里。
- **CR 需要参考答案**，与人工工单那条「不给参考答案」不冲突：那条管「结论对不对」（判的人不能抄），这一条测「检索面够不够」，按 RAGAS 定义必须有 reference 才能拆声明。
- **这两个指标是自研复现，不是 ragas 库**（官方包拖 scikit-network→numba，会顶掉本项目硬钉的 numpy==2.5.3，而 torch 是经 `.pth` 挂进 `.venv` 的）。prompt 为中文（官方为英文），contexts 见两个口径——对外称「KEE 复现版 Faithfulness / Answer Relevance」，不得称「跑了 RAGAS」。
- **裁判模型与生成模型同为 qwen2.5:7b**：自偏好偏置未经外部对照，第三节的一致率/κ 是它唯一的定级证据。
- **读数一律为报告值，不进门禁**（用户 2026-10-16 裁决：LLM 判定不可机械复现，门禁只收机械可复算判据这条纪律不变）。
- **未重跑生成**：输入是真人标签配对的那代留档产物 ⇒ 既有人判读数零作废；代价是这些指标量的是**那一批已判过的输出**，不是「系统此刻的输出」。
- **Top-5 口径只在 cited_ids ⊆ 复跑 Top-5 的行上可比**（对齐率见成本节前那行）；不齐的行是检索跨代漂移，不是标签错。
- **Answer Relevance 的全行档把正确拒答记成 0 分**（RAGAS 官方就这么算），单独引用它等于把「拒得对」说成「答得差」。
- **Faithfulness 的第二步用了一次批量判定**（一题的 N 条陈述合成一趟 7B 调用，官方是逐条）：实测原口径 67 题 × 两口径要 ~740 次调用、约 2 小时，批量版 ~5 次/题。偏离买到的代价是模型一次要看完全部陈述、可能漏答——漏答一律记「判不出」进不了分母，而「证据换成别题的分数必须掉」那道护栏就是专门兜这种失明的；要跑逐条原口径加 `--per-statement`。
- **Answer Relevance 的绝对值不能与论文里用 OpenAI embedding 出来的数比**：这里的余弦来自本地 BGE-M3（dense，与在线检索同口径、float16/cuda），它本身的余弦分布就压在 0.55–0.75 这一段。可解释的标尺是第三节那条对照：同一题配**别一题的答案**时均值掉 0.2918、10/10 逐对下降——所以 0.6582 该读成「相对错位约有 0.29 的间距」，不是「相关性 65.8% 合格了」。
- **Faithfulness 与「数字落地率」不是一回事**：前者是逐条陈述的 NLI 支持性（LLM 判、不可复算），后者是结论数字是否出现在被引正文（机械、可复算）。两者并列是为了看分歧，不是互相验证。

- 检索复跑对齐：evict 7B 后复跑 67 题检索耗时 38.3s；cited_ids ⊆ 复跑 Top-5 的行 67/67
