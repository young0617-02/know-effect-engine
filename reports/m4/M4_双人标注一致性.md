## 二、真值表：210 行长什么样

按 `(section gold, strict gold, 第二人 B)` 三元组分桶。`000`/`111` 是三方一致，**其余 4 桶共 34 行**才带信息；

| 000 | 149 | 三方都不认 | — |
| 111 | 27 | 三方都认 | — |

## 六、这轮**没有**关闭的敞口（必须写清，别让 0.83 被读成解决了校准）

风险册里那条「ECE 校准敞口」写的处置是「真正缺的是**有方差的正确性标签**（待双人标注）」。
本轮造的工单测的是**块级相关性**（`b_directly_answers`），它修的是**评测集的 gold**，
**不是** `answer_correct`（这道题系统给的答案对不对）。两者不是一回事：

- 相关性标签 → 让 Recall/Hit 的尺子可信（本轮已在做，25 题已到手）。
- 正确性标签 → 才是把复合分从「规则分」变回「概率」所需的那个**有方差的 y**。

所以 `⑤ ECE 敞口` 这条**仍然开着**，且下一张工单的形状已经确定：**每题一行**（不是每块一行），
判「这一题系统给出的结论对不对、且是否被它所引的证据支持」，
**53 行**（= 可判校准集的规模，`m3_answer_probe` 里「可判校准集(有logit)」就是 53：58 道可答题中 `answer` 42 + `tentative` 11；这正是校准需要 y 的那批），
比本轮 547 行**便宜一个数量级**。结论文本与所引块现成在 `var/gate0/m3_confidence_probe.json`
（58 行，含 `question / conclusion / cited_ids`，也含 `reference_answer`——**这张工单不能把 reference 显示给标注人**，
否则就成了抄答案；只给「问题 + 系统结论 + 所引块正文」）。

## 七、待裁决（三项，要用户拍；我不自行改判据也不自行改 gold）

**① 判据补哪条规则——一问两问怎么算。** 两个选项的后果不同，我给推荐：
- **甲（推荐）**：逐块判「**是否直接回答了其中某一问**」即算 1。第二人本轮的判法就是这个，**已判的 210 行不用重标**；配套要做的是给每题加一列**机器算出的「问数」**（脚本可从题面得出，不占人力），让「该题的 gold 是否覆盖全部子问」成为一个**可从标签推出的题级判定**——检索要凑齐两块才答得全，这本来就是 Recall 该管的事。
- **乙**：必须**答全所有子问**才算 1。改动小但后果大：q-013×3、q-025×1 共 4 行翻成 0，**而 q-025 的 gold 自己也只是半答，翻完该题池内没有任何块能算 1 → gold 空 → 这道题不再可判**。要走乙，就得同时改题面或改 gold，那是第二项裁决的活儿。

**② gold 要不要按裁决改（这会动检索读数，必须走三件套）。** 本轮点名两处：
- **漏标**：q-014 的 chm-ifspec §1.2、q-025 的 chm-runbook §4.1（若取甲口径则一并进 gold）、q-012 的 ene-compliance §2.1（弱）。
- **扩收**：q-008 的 strict gold 应从 3 块缩到 1 块（只留 fin）。
改 gold = 改尺子：会**同时**移动 Hit@5 与 strict Recall@5 的读数。按仓库纪律走「**改需求条款 + 记裁决 + 保留改前实测值**」，版本升《项目定义》V1.8 / 《技术方案》V1.0.8，**且不覆盖 M2 的基线 artifact**（`m2_eval.json` 留原件，重跑另存）。
我的建议：**先把剩下 38 题标完拿到全库分歧面，再一次改 gold、一次重跑基线**，不要边标边改——否则改前改后的读数没法比。

**③ 判据第三句要不要写进工单。** 「描述性块 ≠ 规范性答案」这条（q-012 cand10 那 1 行）我建议**写**，因为它同时解释了本轮唯一一行「B 判松」，而且后面 38 题里「部署了几台 / 达成率多少」这类块很多，不写会重复产生同类噪声。

判据建议原文（批准后替换 `scripts/m4_build_annotation_sheet.py` 的 `JUDGEMENT_LINE`，只加不改主干）：

```
判据只有一条：**这一块的正文里是否直接含有能回答该问题的内容。**
三条细则：
1. 题面若含两问（例：「表决逻辑是什么，能不能改整定值」），按**回答其中任一问**判 1；
   该题的 gold 是否覆盖全部子问由脚本另算，不需人判。
2. 题面点名了主体（清算平台 / 某装置 / 某条线）时，**其他行业或其他项目**的同名章节即使数字相同也算 0；
   题面未点名主体、把几条线并列问到时，各线的块都算。
3. **叙述型**块（部署了几台、达成率多少、周期几天）不算直接可答，除非正文里有带强制性
   （必须 / 不得 / 只能 / 一律）的句子正面回答该问。
```

## 八、总结：已验证 / 未验证

**已验证（真机跑出、可复跑）**
- 210 行 / 25 题的双口径 Kappa 与**按题聚类**的重采样区间；差值在同一批抽样里算，2000/2000 次同号。
- 9 行真分歧**逐行读了块全文**并给出裁决（`var/gate0/kappa_a2.json` 的 `divergence_samples` 每行带
  `question / chunk_text / reference_answer / n_sub_questions`，第三节表格与之一一对应，可在 artifact 里复看）。
- 全库尺子扫描落成 `scripts/m4_gold_defects.py`（一问两问 11 题、gold 跨行业 1 题），离线可跑、证据 `m4_gold_defects.json`。
- section 正例中 48.2% 被第二人否掉、其中 44.6% 第一人自己的 strict 也不认。
- 工单本身合法：无非法值、无残留 TODO、0 行截断、0 行父块；`scripts/m4_kappa.py` 允许半成品出数（这正是这个停点能生效的原因）。
- 修掉了两处会误导人的东西：分歧桶名的越权结论、`kee.eval.kappa` 与 `m4_kappa` **写同一个 `kappa.json`**（跑一次旧 CLI 会静默覆盖双人标注证据；现分为 `kappa_gate0_single.json` / `kappa_a2.json`）。单测 157 全过。

**未验证（别当结论用）**
- **全库 gold 缺陷面**：跨行业扩收只由词典法扫出 1 处，词典是字面的，隐含主体的问法扫不出来。
- **外推**：Kappa 是 25 题 / 210 行的数，剩下 38 题没标；分歧集中在 5 题，所以区间宽（strict 的下界只到 0.71）。
- **判据变更后的数**：第七节任一规则批准后，本轮 210 行里有 4–8 行的含义会变，0.8321 不是「定了判据之后」的读数。
- **⑤ 的 ECE 敞口没有因为本轮关闭**（见第六节：本轮测相关性，不测正确性）。

**裁决结果（用户 2026-10-12 选定）**：主口径取 **乙**（一块必须能**独立答全**该题全部内容），
「描述型块 ≠ 规范性答案」**写进判据**。登记在《项目定义》V1.8 / 《技术方案》V1.0.9。

**三处与我上文说法不同的实测结果**：

1. **我推荐错了方向。** 上文推荐甲（答任一问即算 1），理由是「已填的 210 行不用动」。
   但甲有个我当时没说透的后果：**只检到一半的检索也会被判命中**——
   对一个立身之本是「答不出就拒」的知识服务，这是更坏方向的假绿。乙没有这个问题。
2. **我把乙的代价说重了。** 上文写「走乙，q-025 会**无 gold 不可判**」。
