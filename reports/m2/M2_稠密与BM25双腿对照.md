## 差异清单

1. **纯编号问句上 BM25 的头部更干净**：gold 两兄弟占满 #1/#2，稠密把 `#1.2#c2` 压到 #4，中间插进 `IF-FIN-0028`、`IF-FIN-0013`。对「按编号查这条接口」的用法，稠密会把**别的接口的定义**排到目标接口的兄弟块之前——这不是排序瑕疵，是把 0028 的上限当成 0012 的上限的风险位置。
2. **两腿的错法形状不同**：稠密的干扰项是**同族邻居**（0028/0013/0031 都是金融接口定义），BM25 的干扰项是**跨行业词面碎片**（能源文档里那句「接口编号采用 IF-ENE-加四位流水号形式」被捞到 #3）。前者是语义相近，后者是 token 相同，两者的修法不是同一个。
3. **前 20 名高度重合，差异集中在头部**：Q1 的 Jaccard@20 = 0.82 而 Jaccard@5 = 0.43——两腿候选池基本是同一批，只是**头两名给谁**不一样。这决定了这类差异只能靠名次读，靠 Recall@5 读不出来（Q1 两腿 Recall@5 都是 1.0）。
4. **编号 + 上下文双升**：从 Q1 到 Q3，稠密 Top-1 cosine 0.6128 → 0.7286（+0.116），gold 兄弟块 #1/#4 → #1/#2；BM25 Top-1 12.05 → 28.76（×2.4）。两条腿都因为上下文更确定，**没有哪条腿是只靠上下文受益的**。
5. **延迟比 g03 报的更极端**：本批稠密 37–70ms（嵌入占 86–93%）对 BM25 2.9–7.8ms，约 8–13×。BM25 腿是纯服务端计算，客户端只发字符串。
6. **口语化问句在词面不缺货时两腿平局**（Q2 两腿 gold 都 #1）。

## 编号为什么不是 BM25 的靶心：分词选择性实测

用单 token 探服务端命中面（`limit=30`，打满即记 `≥30`）：

| 查询串 | 命中块数 | Top-1 |
|---|---|---|
| `IF-FIN-0012` | **≥30** | `#1.2#c1` |
| `IF-FIN` | ≥30 | `fin-ifspec#1.1` |
| `FIN-0012` | **2** | `#1.2#c1` |
| `0012` | 0 | — |
| `IF` | 23 | `fin-ifspec#2.1` |
| `FIN` | 2 | `fin-ifspec#1.1`（编号规则章节） |

结论：整串 `IF-FIN-0012` **不是**一个精确项，它被拆成 `IF` 与 `FIN-0012` 一类片段；唯一的区分力在**连字符后半段**（`FIN-0012` 只命中 2 块），前缀 `IF` 是纯噪声源（23 块）。所以「纯编号题 BM25 必胜」的前提是「同族编号的后半段互不相同」；一旦编号变成 `F0012`、或流水号带前后缀粘连，这条腿的选择性就没了。附带一条：`0012` 单独 0 命中，说明纯数字段根本没进倒排。

## 对照组：一条**假设被推翻**的实测

上面 Q2 其实没测到稠密的强项——题面里「操作员 / 拒 / 系统建议 / 回路」都是原文实词（`操作员拒绝` 探得 24 块、`回路` 16 块），BM25 根本不缺词面。为把机制照出来，另跑一条**构造的**低词面重合问句（不在评测集内，`--control`）：

> 厂里那套自动给数值的玩意儿，被人连着压了三回不搭理，它自己会消停多长时间？

预期「词面重合归零 → BM25 饿死、稠密接住」。实测**两腿全灭**：

| 腿 | gold 名次 | Top-1 | Top-1 分 |
|---|---|---|---|
| 稠密 | **未进前 20** | `ene-runbook#2.2`「SCADA 主站的实时数据刷新周期为 2 秒」 | 0.5430 |
| BM25 | #12 | `chm-runbook#2.2`「GMP 数据完整性核查」 | 10.23 |

两腿前 20 名交集为 **0**（Jaccard@20 = 0.0）。

要修正的判断：**「口语化是稠密的靶心」在本语料上不成立**。问句里一个领域名词都不留时，稠密并没有接住「压了三回不搭理 → 连续 3 条建议被操作员拒绝」这层同义映射，而是漂到「自动给数值 → 实时数据刷新」这种表层相似上。这条同时也解释了 g03 里 `sparse_only` Recall@5 0.7612 ≈ `dense_only` 0.7618 为什么几乎相等：**很多题上两腿是同一批错，不是两腿各补一半**。

顺带一个可用信号：稠密腿 Top-1 cosine 从三条正常问句的 0.613 / 0.616 / 0.729 掉到 0.543。n=1，不足以定阈值。

## 本次未验证 / 边界

- **n=1 每条**，只读名次差异，不读任何召回率结论；绝对值受自建语料与章节级 gold 影响（口径同 `g03_ablation.py:166-168`）。
- **没跑 hybrid(RRF) 与 rerank**，线上最终 Top-5 与本文的腿内排序不同；本文刻意关重排。
- **章节级 gold 污染了「谁更好」的判定**：Q1/Q3 的 `#1.2#c2` 只因为与 `#c1` 同章节就算 gold，它本身不含「500 万元」。若只按严格 gold（`#c1`），两腿**都排 #1，是平局**——第 1 条差异的强度因此要降级为「章节内兄弟块的聚拢度差异」，不是「找没找到答案」。
- gold 取自问句更完整的评测题（q-018 题面含「单笔汇款金额上限」），套到裸编号 Q1 上偏窄：按编号查询的真实意图通常是「这条接口的全部规定」，那样 `#1.2` 的三个子块都该算相关。
- 生成侧未测（Ollama 未启动，本次不依赖）；`check_stack.py` 因此报 FAIL，其余 Milvus/PG/Redis 均 healthy。
- 对照组是**为验证机制而构造**的，不能当作「口语化题普遍如此」的证据——那件事的证据是评测集 14 道口语化题加 g03 分类别 Recall。

## 待裁（不在本次范围内动手）

1. 编号类问句要不要给稠密腿加护栏：把 `IF-XXX-NNNN` / `GB/T …` 这类整串从 chunk 标题抽成 metadata 精确字段，命中整串时直接置顶，不依赖 jieba 碎片。
2. 稠密腿的 cosine 地板能不能做成拒答/转人工信号：需在评测集 68 题上取分布、并和「无答案」类题的分布对比后才可定，n=1 不够。
3. 低词面重合口语化题是**改写（`rewrite_mode`）的目标场景**还是**拒答目标场景**：C1 这条现在两腿都召不回，改写腿（q-050 那类有锚点的题）受益有限，需要先在评测集里造一小批真·低重合题才能判。
