## 0. 一页结论

- **形态**：FastAPI 单体服务 + LangGraph 类型化状态机；Milvus 混合检索、PostgreSQL 唯一权威源、Redis 非权威缓存、Ollama 本地生成、React 前端经 Nginx 同源反代。
- **强制点**：权限过滤在**检索层**（Milvus filter expression）；复核闸在**答案层**（未复核可检索、不进答案）；审计**追加写 + 禁改触发器 + 权限面**。
- **可重建**：PostgreSQL 是唯一权威源，Milvus 索引可由权威源 + 向量物料重建；写入走 Outbox，每日对账收敛。
- **只做本地**：嵌入/重排走宿主 CUDA，生成走 Ollama，OCR/表格/公式走本地 ONNX；不调用外部模型 API。
- **不夸大**：ECE 不达标、整机断网端到端未证、图表不做语义理解、公式准确率未验收；这些均作为边界保留。

## 1. 技术形态一句话

FastAPI 单体服务 + LangGraph 类型化状态机编排的**内网 RAG 知识服务**：Milvus 做混合检索（服务端 BM25 + 稠密 + RRF + 重排），
PostgreSQL 做唯一权威源与审计，Redis 做非权威检索缓存，本地 Ollama qwen2.5:7b 做生成，
React 19 前端经 Nginx 同源反代，Prometheus + Grafana 做可观测，整套用 Docker Compose 单机起。
图片/图表只做本地 OCR（MinerU/PP-OCR），把图内文字转成普通文本；不做图表语义理解，也不调用外部视觉模型。生成仍由纯文本 7B 完成。

## 4. 关键实现机制

### 4.1 检索与权限（`src/kee/retrieval/`）

- **中文 BM25 在 Milvus 服务端做**：集合建 `jieba` 分析器的稀疏向量字段，用 BM25 稀疏索引出词法命中，不在宿主重算 IDF。
  实测：jieba 分析器 Recall@5 **0.7612** vs 默认分析器 **0.399**。
- **稠密腿**：BGE-M3 输出 1024 维向量，`FLAT` + `COSINE` 精确检索（语料规模小，避免 ANN 近似损失污染消融结论）。
- **融合与重排**：稠密腿 + 稀疏腿 → **RRF**（`rrf_k=60`）→ BGE-reranker-v2-m3 重排 Top-20 候选。
  表格行块采用「守住融合名次、只用重排分数」的策略，绕开交叉编码器在 0.97–0.999 饱和区对同表各行只差 1e-3 的排序噪声（[pipeline.py:138](file:///D:/project/know-effect-engine/src/kee/retrieval/pipeline.py#L138)）。
- **权限唯一强制点**：`build_filter_expr(ctx)` 按角色密级上限、行业、项目生成 Milvus filter expression；
  标识符先过白名单字符校验再拼接，防表达式注入（[rbac.py:56](file:///D:/project/know-effect-engine/src/kee/retrieval/rbac.py#L56)，`tests/test_rbac.py` 6 条注入用例）。
  身份来自登录账号而不是可伪造的请求头（`KEE_ALLOW_HEADER_IDENTITY` 默认 false）。
- **缓存与降级**：Redis `SearchCache` 非权威、TTL 可驱逐；**权限表达式与改写模式进入缓存键**
  （[cache.py:25](file:///D:/project/know-effect-engine/src/kee/retrieval/cache.py#L25)、[pipeline.py:188](file:///D:/project/know-effect-engine/src/kee/retrieval/pipeline.py#L188)），不同身份/不同改写配置不会共用缓存。
  检索层把稠密腿空结果、超时、量纲异常等收敛成 **13 个降级原因类**；`top_score > 1` 直接标记 `score_scale_out_of_range`，
  防止静默退化成 BM25 后拿几十的分数去过 0–1 量纲的阈值。
- **查询改写**：启发式触发 + 准入校验（禁止引入原查询没有的数字）+ 截断打捞；实测单次 P95 **843ms**，已吃满 800ms 检索门禁，因此默认 `off`。

### 4.2 编排与答案（`src/kee/qa/`）

- **LangGraph 七节点有限状态机**：`sensitive_gate → rewrite → retrieve → retrieval_gate → generate → enforce → confidence`，
  三处 `conditional_edges` 可提前 END（[graph.py:127](file:///D:/project/know-effect-engine/src/kee/qa/graph.py#L127)、[:445](file:///D:/project/know-effect-engine/src/kee/qa/graph.py#L445)）。
  指标侧出口标签是 **10 值闭合枚举**（`answered / sensitive / retrieval_gate / generation_failed / unparseable / declared_no_evidence / no_citation / marginal_evidence_refusal / empty_conclusion / graph_exception`），
  闭合枚举在 [metrics.py:55](file:///D:/project/know-effect-engine/src/kee/obs/metrics.py#L55)。
- **引用强制**：结论与引用同轮产出；无来源不出结论；**证据勉强过线不得逐字搬运出结论**（`marginal_evidence_no_derivation`）（[graph.py:301](file:///D:/project/know-effect-engine/src/kee/qa/graph.py#L301)、[answer.py:319](file:///D:/project/know-effect-engine/src/kee/qa/answer.py#L319)）。
- **答案层复核闸**：`AnswerEngine.gate_unreviewed()` 在检索节点**之后**摘除未复核版本的证据（[answer.py:284](file:///D:/project/know-effect-engine/src/kee/qa/answer.py#L284)）；
  未复核内容仍可被检索（复核人得看得见），但不进答案证据面。摘光后走既有「无充分依据」出口，
  并通过 `refusal_reason`（`no_evidence` / `all_evidence_unreviewed`）和 `unreviewed_evidence_count` 把「库里没资料」与「有资料但没复核」分开。
- **敏感闸与转人工**：密级 3 命中时允许答但必须 `needs_human=true`；非作答题用另一把尺判「该不该不答」。
- **置信度 = 复合规则分**：`0.45×检索 + 0.35×引用一致性 + 0.20×模型自评`；对外自带 `score_basis=rule_composite_not_probability`；
  温度单一来源 `kee.qa.answer.load_calibration_temperature()`，T=1.0；`fit_temperature` 有拒绝分支（零方差标签 / 结构零值同义反复）。
- **流式**：`POST /api/v1/answers/stream` 走 SSE，**token 级**；实现方式是"从未闭合的 JSON 信封按路径读已成形字段"，
  **不需要**拆成两趟生成；被撤回的片段带显式标记，前端不得静默删（[streaming.py:62](file:///D:/project/know-effect-engine/src/kee/qa/streaming.py#L62)、[stream_json.py:111](file:///D:/project/know-effect-engine/src/kee/qa/stream_json.py#L111)）。
- **多轮**：会话轮次 + 指代消解；`langgraph-checkpoint-postgres` 已声明但 Checkpointer **本轮未接**（已知债：无断点续跑）。
- **行为等价的证明方式**：`scripts/m3_graph_equivalence.py` 按 commit sha 从 git 抽旧实现当 oracle 逐出口差分，豁免项显式登记——**不拿"单测过了"当等价证据**。

### 4.3 知识接入与版本治理（`src/kee/ingest/` + `src/kee/db/`）

- **双后端解析（`auto` 默认按页路由）**：`pdf_parse_backend=auto` 不再按整份文档平均判定，而是逐页决定：
  文本页走 pypdf 保留精确字符；**单页可抽取字符 < `pdf_min_chars_per_page=40`** 的页只在该页渲染给
  **本地 MinerU-ONNX 后端**。图表/图片区域本身**不是触发条件**；显式 `mineru_onnx` 才整份强制。
  页级 MinerU 走 `MinerUPdfParser.parse_pages(page_numbers=...)`（[mineru_onnx.py:674](file:///D:/project/know-effect-engine/src/kee/ingest/mineru_onnx.py#L674)）：`pypdfium2` 按 `ocr_dpi=150` 渲染选定页 →
  PP-DocLayoutV2 版面 → PP-OCRv6 det/rec → SLANet-plus 表格结构，三处 `ort.InferenceSession(providers=["CPUExecutionProvider"])`
  （[mineru_onnx.py:93](file:///D:/project/know-effect-engine/src/kee/ingest/mineru_onnx.py#L93)、[:172](file:///D:/project/know-effect-engine/src/kee/ingest/mineru_onnx.py#L172)、[:311](file:///D:/project/know-effect-engine/src/kee/ingest/mineru_onnx.py#L311)）；
  公式 PP-FormulaNet 按需加载。页级后端失败或没产出文本时**回退整份文本层 + 内嵌位图 OCR**，不静默降级。
- **文本页仍抽内嵌位图**：`_append_pdf_images` 在 `media_scan_text_pdf=true`（默认）时用 pypdf 枚举**文本页**的 `page.images`，
  逐张走 PP-OCR，结果追加到「第 N 页图片与图表」章节；已交给 MinerU 的 OCR 页不会重复跑位图 OCR。
  因此「正文可抽字、中间夹一张位图」**不会整块漏掉图内文字**。
  **缺口**：矢量图 / 文字转曲的图表不是 pypdf 的 `page.images` 对象，文本页不会触发 MinerU 版面，图内文字不会被 OCR；
  `pdf_parse_backend=pypdf` 或 `media_scan_text_pdf=false` 会直接关掉图片 OCR 通路。
  另外单文档最多 20 张、小于 1024 像素的图不单独 OCR，超出/损坏/不支持的图片会跳过并写 `parse_notes`。
- **历史口径与阈值**：`KEE_PDF_PAGE_ROUTING=false` 时回到旧行为——整份文档平均可抽取字符 < 40/页才整份转 MinerU。
  `pdf_min_chars_per_page=40` 是**工程启发式默认值**，不是实验标定出来的最优值；仓库里没有阈值扫描或真实 PDF 标注实验。
  按页路由解决「文字为主 + 少量扫描/图片页」的混合文档；文本页上的矢量图表仍需后续按区域版面检测补足。
- **按页路由验证（2026-10-27 实现后）**：`tests/test_page_routing.py` 8 项；真实混合 PDF（1 页文本 + 1 页扫描）

  文本页不触发 MinerU，内嵌图走 `IMG-1` OCR。
- **生产语料没走 OCR**：当前 193 个知识块来自代码内置的行业文档（`src/kee/ingest/corpus_data.py`），属于文本层路径；

- **准入**：格式白名单 + `checksum` 指纹查重 + 密级/元数据三级取值（表单 > front-matter > 推断，逐级告警）（[admission.py:55](file:///D:/project/know-effect-engine/src/kee/ingest/admission.py#L55)、[metadata.py:54](file:///D:/project/know-effect-engine/src/kee/ingest/metadata.py#L54)）。

### 4.4 权限、审计与账号（`src/kee/api/auth.py` + `src/kee/db/pg.py`）

- **账号**：口令 **`hashlib.scrypt`**（n=2^14、r=8、p=1、dklen=32，每用户独立盐）；会话令牌只存 **SHA-256 摘要**，
  `user_session.expires_at` 控 TTL；退出默认**撤销全部会话**，管理员可对单用户强制下线（[auth.py:40](file:///D:/project/know-effect-engine/src/kee/api/auth.py#L40)、[:81](file:///D:/project/know-effect-engine/src/kee/api/auth.py#L81)、[:106](file:///D:/project/know-effect-engine/src/kee/api/auth.py#L106)、[:154](file:///D:/project/know-effect-engine/src/kee/api/auth.py#L154)）。
- **注册约束**：自助注册不能选 `knowledge_owner / system_admin`；唯一例外是库里一个账号都没有时的首个注册者（鸡生蛋例外，首次启动须在受控网络完成）。
- **身份通道**：登录令牌是权威身份；请求头通道 `KEE_ALLOW_HEADER_IDENTITY=false` 默认关闭。中文部门/项目值两端必须百分号编码（`encodeURIComponent` ↔ `unquote`）。
- **权限**：RBAC 强制点唯一在检索层；`chunks/batch` 读引用正文时走同一套三维过滤，越权与不存在合并成 `hidden`；
  `reviews/pending` 按调用者可见范围过滤。知识库列表与文档详情的口径差异见 §7 第 11 条。
- **审计**：`audit_log` 追加写 + `BEFORE UPDATE OR DELETE` 触发器（[pg.py:180](file:///D:/project/know-effect-engine/src/kee/db/pg.py#L180)）。
  ⚠ 触发器**不覆盖 TRUNCATE**；`TRUNCATE` 靠**权限面**挡住：表与触发器函数属主换成 NOLOGIN 超级用户 `postgres`，
  应用连**非特权角色 `kee_app`**（表上仅 `INSERT, SELECT`，序列另授 `USAGE, SELECT`）。
  原角色 `kee` 是容器 initdb 造的 bootstrap 超级用户，PG 禁止摘它的 SUPERUSER（实测 `permission denied to alter role`）⇒
  应用改 `kee_app`、`kee` 设 `NOLOGIN`、新建 `kee_admin` 留管理入口。授权必须排在降级之前，否则会停在半完成状态。
  **现场验证由应用角色自己那条连接试探**（`harden_audit_store.probe_bypass`，2026-10-19）：
  以 `kee_app` 执行 `TRUNCATE TABLE audit_log` 与 `DELETE FROM audit_log` **双双被拒**，两条都停在权限阶段
  `InsufficientPrivilege: permission denied for table audit_log`，审计行数 1790 → 1790 一字未动。
  ⚠ 分层说法要准：**今天挡住的是权限面**，触发器是第二层（防日后重新 GRANT 或以属主身份操作）。
  残余风险如实保留：超级用户仍可整表抹除且审计零痕迹，故清场动作写在**表外凭据** `var/gate0/audit_reset.json`。
- **错误契约**：`E4xx` 客户端 / `E5xx` 服务端 / `E9xx` 依赖，结构含 `code/message/trace_id/retryable`；
  统一在 `_fail()` 一个咽喉点计数（[app.py:77](file:///D:/project/know-effect-engine/src/kee/api/app.py#L77)）。

### 4.5 可观测（`src/kee/obs/`）

- **私有 `CollectorRegistry`**（不用全局）：`create_app()` 在一进程里被多次调用，全局注册表会撞重复注册。
- **19 个 `kee_*` 指标族，标签全闭合**：出口标签取 `state["gated"]` 实际值（不从 `notes` 猜字符串）；
  `degraded` 收敛成 **13 个原因类**（`degraded_class()`），否则每个新分数都会变成一条新时间序列。
  ⚠ 计数别数 `# TYPE kee_` 行——`prometheus_client` 会在首次观测后追加 `_created` 伪族，实测会在 23/24/32 之间浮动，**声明族数是 19**。

  九个噪声 logger（httpx/httpcore/urllib3/pymilvus/transformers…）压到 WARNING。
- **Langfuse**：默认关闭，后台线程 + 队列满丢弃并计数，**目标地址必须回环/RFC1918/链路与白名单名**（`in_domain_host`）；

## 7. 已知边界与技术债（如实列出）

1. **API 未进容器**（ADR-12 定案维持现状）：`torch` 不在 pyproject 是根因；实测 CPU 路径合成检索 **5166.9ms**（fp16 CPU 更慢，26153.7ms）对 800ms 门禁 ⇒ 容器化只装 CPU torch 不是"慢一点"而是把门禁变成不可达；要 GPU 就得拉 GB 级 CUDA 镜像。
2. **ECE 不达标**：真人标签下 0.2006 > 0.10，方向为欠置信；温度缩放两档均拒绝采纳。
3. **断网端到端未证**：`internal: true` 断掉宿主↔容器通路，`enable_ip_masquerade=false` 在 Docker Desktop 上实测切不掉容器出网。
4. **图表语义未做，且矢量图表存在 OCR 缺口**：图片/图表只保留 OCR 文字，纯图形或无文字的图表不会产生可检索内容；不做趋势/坐标轴理解。
   文本层够厚的 PDF 不触发 MinerU 版面，**矢量图 / 文字转曲的图表**不是 `page.images` 位图，图内文字不会被 OCR；
   内嵌位图仍会走 `_append_pdf_images`。`pdf_parse_backend=pypdf` 或 `media_scan_text_pdf=false` 时连位图 OCR 也会关闭。
5. **公式准确率未验收**：PP-FormulaNet_plus-M 能输出 LaTeX，但复杂分式/矩阵结构仍可能出错；正式使用前需按行业样本建立准确率门槛。
6. **已有索引不回填**：图片/公式是解析期能力，开启或修改后只影响新摄取/重新摄取文档；已有 24 篇纯文本索引不会自动长出图片文字。
7. **检索侧词法缺口**：口语化查询与书面证据词法不重合（q-044 排名在噪声级别，第 1 名曾只领先第 2 名 0.0002）。
8. **`/metrics` 免鉴权**（敞口未闭）：前提三条同时成立——只绑回环、Nginx 不反代该路径、标签无业务内容。
9. **Langfuse 容器未实跑**：代码侧已用本地采集器**实采**过载荷；当前 `.env` 开关为 true 但目标 `127.0.0.1:30090` 未起，状态端点会累计 `errors`。要么起容器，要么关开关。
10. **业务两条指标不可测**：需要上线前基线与真人时间维度。
11. **读路径的三维口径不完全一致**：检索、答案、`chunks/batch`、`reviews/pending` 按密级 + 部门 + 项目过滤；
    **知识库列表**的 `industry` 查询参数当前是「替换」账号行业而非取交集（[app.py:529](file:///D:/project/know-effect-engine/src/kee/api/app.py#L529)），
    **文档详情**只判密级、不判部门/项目（[app.py:548](file:///D:/project/know-effect-engine/src/kee/api/app.py#L548)）。
    这两条只影响元数据面（详情不返回正文），但若对外承诺「所有读路径完全一致」需先收紧。
12. **账号页改角色会清空部门/项目范围**：前端 `grantRole(username, role)` 默认提交空数组（[auth.ts:79](file:///D:/project/know-effect-engine/frontend/src/api/auth.ts#L79)），
    后端 `set_role` 无条件覆盖两列（[auth.py:159](file:///D:/project/know-effect-engine/src/kee/api/auth.py#L159)）；页面没有部门/项目输入。
    改角色后需要走管理 API 显式回填，否则隔离范围会被静默放大成「不限定」。
13. **冷启动代价**：8GB 卡上模型冷装载会显著抬高第一呼（本机实测 UI 首问 12.9s、M4 冷态首字 2056ms；热态 322ms）。
    验收脚本必须先 `api_warm.py` 预热，不能把冷态读数当门禁。
14. **`AccessContext.department` 是死字段**：从未参与过滤（[rbac.py:41](file:///D:/project/know-effect-engine/src/kee/retrieval/rbac.py#L41)）；「部门」实际看 `industries`。
