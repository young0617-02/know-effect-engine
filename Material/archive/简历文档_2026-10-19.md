## 项目经历

### 知效引擎（KnowEffect Engine，KEE）· 企业内网交付知识服务引擎
**独立设计与全栈实现（单人，需求→架构→开发→评测→部署→验收）· 2026.10**

面向数字技术服务企业的**项目与行业知识问答系统**：交付文档入库后，员工可用自然语言追问，
系统只依据**有权查看且经人工复核**的证据作答，每条结论带出处，证据不足时明确拒答或转人工。
整套系统单机内网部署、本地推理、零外部 API 调用。

**核心成果（本地实测，n 与口径均可复算）**

- **检索质量达门禁**：自建评测集 80 题 / 68 可判，`Hit@5(strict) 98.53%`、`Recall@5(strict) 97.79%`、`MRR 0.9706`、
  `P95 检索 302.8ms`（门禁 95% / 85% / 0.75 / 800ms）。为达成该结果，把 Milvus 换成**服务端 BM25 + jieba 中文分析器**
  方案并实测对比（Recall@5 **0.7612 vs 默认分析器 0.399**），再以 RRF 融合稠密腿 + BGE-reranker 重排。
- **答案可信机制落地并逐条验证**：LangGraph 七节点状态机（出口标签 10 值闭合枚举）；引用强制（行级引用落 gold **98.39%**、
  零引用结论 **0 条**）、无依据必拒答（**7/7**）、密级敏感必转人工（**5/5**）、结构化输出首次成功率 **100%（58/58）**。
- **端到端延迟达门禁**：仅作答轮次 `p95 4118.8ms`（门禁 <6s，n=76 净环境四轮复测）；
  流式**首个可读字** `p95 859.2ms / p95 < 1.2s` 达标——口径钉在 `first_visible_ms`，
  明确否决了用「信封首字符」冒充首 token 的写法。
- **自建评估体系（本项目最难也最有差异化的一块）**：设计并实施**双人标注 63 题 / 547 行**，用 Cohen's Kappa
  按题聚类重采样算 95% CI，独立复现出「宽松 gold 口径注水」并把门禁尺子换成严格口径（阈值数值一个未动，改的是测哪把尺子）；
  真人正确性标签 67 行回收后算出 `accuracy 96.77%`、`ECE 0.2006`、`AUC 0.7833`，并据零方差标签证据**否决温度缩放上线**。
- **RAGAS 两指标自研复现 + LLM 裁判对照**：Faithfulness(cited) **0.9866**（n=62，CI [0.9651,1.0]）、Answer Relevance **0.6582**；
  未引 ragas 官方包（其依赖闭包会顶掉硬钉的 `numpy==2.5.3`，且默认走 OpenAI 客户端与"数据不出域"冲突）。
  同轮把 LLM 裁判与真人判做一致性对照（一致率 86.36%，**κ = −0.0645**）——**据此判定该裁判不可充当人工初筛**，读数只作报告值不进门禁。
- **单机算力约束下的模型驻留方案**：在 **8GB 单卡**上实现 BGE-M3 + BGE-reranker 与 7B 常驻共存、空闲超时释放，Gate 0 实测**零 OOM**；
  并为容器化决策做了设备对照实验（同一套权重一次检索：`cuda+fp16 178.1ms / cpu+fp32 5166.9ms / cpu+fp16 26153.7ms`），
  用数据说明"只装 CPU torch"会把检索门禁变成不可达，而不是"慢一点"。
- **可观测与工程闭环**：`/metrics` 暴露 **19 个自定义指标族**（私有注册表 + 全闭合标签，杜绝高基数与业务内容外泄）、
  Grafana **15 面板 + 9 条告警**、结构化 JSON 日志以同一 `trace_id` 串起响应/审计/会话轮次；
  Langfuse 链路追踪按官方 ingestion 批量协议实现（不引 SDK、默认关闭、目标地址域内硬闸门）。
  一键复验 `scripts/ci_local.sh` **十一阶段**（含检索版本回归闸门与服务状态复原），本机全绿。
- **交付形态完整**：FastAPI 23 个 REST 端点 + React 19/TypeScript 前端（问答 / 知识库管理 / 审计 / 账号 / 登录，
  SSE token 级流式 + 多轮会话历史）、Docker Compose 单机起全套（Milvus 3.0 + PostgreSQL 18 + Redis 8 + Nginx），
  合规实测：非回环绑定 0、公网出网 0、云端兜底 False、审计追加禁改（`UPDATE/DELETE` 触发器 + **属主与权限面**挡 `TRUNCATE`，应用连非特权角色）。

**质量与验收**：后端单测 **349 passed**、前端 **37 passed**（5 个测试文件）+ 类型检查与构建干净；
五套端到端验收（M1 17 步 / M3 13 步 / M4 直连 12 项 / 经 Nginx 13 项 / 写路径与复核闸真 HTTP 14 项）全过；
DoD 八条：**达标 3 / 部分达标 4 / 不达标 0**，两处结构性不可测（业务时间维度指标、断网端到端）已书面标注并划出承诺范围。

**技术栈**：Python 3.12 · FastAPI · LangGraph · Pydantic v2 · PostgreSQL（Outbox + 对账 + 触发器） · Milvus（服务端 BM25 + 向量） ·
Redis · PyTorch/CUDA · Transformers（BGE-M3 / BGE-reranker） · Ollama（qwen2.5:7b） · ONNX Runtime 本地版面/OCR/表格结构 ·
React 19 · TypeScript · Vite · Vitest · Prometheus / Grafana · Langfuse ingestion · Docker Compose · Nginx · pytest

## 与目标岗位匹配的能力点

| 岗位常见要求 | 我怎么做的（可追问的具体决策） |
|---|---|
| **RAG 全链路落地能力** | 解析→分块→混合检索→重排→生成→引用校验全链路自建；中文 BM25 走数据库侧分析器而非宿主重算，Parent-Child 分块兼顾命中精度与上下文完整 |
| **Agent / 编排** | LangGraph 有限状态机 7 节点、3 道可提前结束的闸、出口标签 10 值闭合枚举；重构时用 git 抽旧实现当 oracle 做**差分回归**而非只看单测 |
| **评估与度量意识** | 自建评测集 + dev/test 半区隔离（禁止在同一份测试集上调参再报分）+ 尺子指纹（改题干即判「不可比」，不给假的 `regressed=false`）+ 版本回归接入一键复验 |
| **幻觉与可信治理** | 引用强制、无依据拒答、勉强证据不逐字搬运、敏感密级转人工；把置信度**降格为规则分**并在响应里显式声明它不是概率——因为实测该成分 93% 是常数偏移、AUC 0.346 |
| **生产化与运维** | 统一错误码/超时/幂等契约、依赖健康探针（"依赖故障会伪装成一次通过"是实测过的事故）、指标闭合标签防高基数、日志同源 trace_id、单机 Compose、版本锁定清单（取不到就写"未固定 + 原因"） |
| **数据合规与权限** | 检索层唯一强制点做部门/项目/密级过滤，且**权限表达式进检索缓存键**（不同身份不共用缓存，另有测试钉住）；答案层复核闸堵投毒路径；登录令牌 + scrypt 口令 + 会话撤销；审计防篡改——`TRUNCATE` 与 `DELETE` 实测都停在**权限面**被拒（表与触发器函数属主改为 NOLOGIN 的 `postgres`、应用连非特权角色 `kee_app`，而 PG 里 TRUNCATE 需要属主或超级用户身份），`BEFORE UPDATE OR DELETE` 触发器是第二层；验证走**应用角色自己的连接**、审计行数一字未动 |
| **工程权衡与决策留痕** | ADR 表逐条附「依据」列并按证据改判；容器化决策用设备对照实验数据而非直觉；前端选型从 SSR 改为独立构建并接受其成本 |

**面试可展开的三个深度点**（每个都有失败案例与修正过程，不是背概念）
1. 一次"指标误读"的完整回溯：`引用落 gold 仅 23.5%` 曾被写成核心瓶颈，实为三项合取标签被当成引用正确率读，
   撤回后测得行级 100%——由此定下"读数必须写清算的是哪个合取式"的纪律。
2. 8GB 单卡如何把架构逼到墙角：驻留策略、CPU 路径实测、冷启动代价（本机两次实测首个问答 27.5s 与 177.4s，
   导致复验脚本必须新增预热阶段，否则验收会把"服务刚起来"读成失败）。
3. 人工标签的不可自动化：为什么"我来代填第二列"会让整套双人一致性证据当场失效，
   以及 Kappa 为什么**检测不出**这件事（它只比两列标签一致性）。
