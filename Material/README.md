## 2. 建议阅读顺序

1. **需求文档**：先看六痛点与 Epic/US，建立「业务问题 → 验收口径」的框架。
2. **技术文档**：再看关键机制与边界，确认每个能力都有实现与证据。
3. **架构图文档**：把进程、模块、读写路径与权限过滤串起来。
4. **项目简历文档**：最后取简历 bullet、代码定位与面试问答。

## 3. 单一事实源

- **需求与验收**：以《需求文档》为准。
- **实现机制与配置**：以《技术文档》为准。
- **拓扑与数据流**：以《架构图文档》为准。
- **简历写法、代码定位、面试展开**：以《项目简历文档》为准。
- **数字口径**：三份文档引用同一批 `reports/` 与 `var/gate0/` 产物；如果读数更新，先更新产物，再同步三处，**不允许各写一套**。
- **证据产物不可改写**：`var/gate0/` 与 `reports/` 里的既有读数是历史证据；复跑请另存带日期/标签的新文件。
