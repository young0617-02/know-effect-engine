# 需求文档（已实现功能 · User Story 口径）

> **项目**：知效引擎（KnowEffect Engine，代号 KEE）· 面向数字技术服务企业内部的项目与行业知识服务引擎。
> **一句话**：把「咨询—实施—运维」全链路沉淀下来的交付知识，做成**可追问、可溯源、可评估**的内网 RAG 知识服务。
> **文档口径**：以下每条 Story 都对应仓库里**已实现并可复跑**的代码路径；「实测」列的数字全部是**这台机器上的本地实测**，
> 语料为自建行业文档集（金融 / 能源 / 化工交付场景，24 篇文档、193 个知识块），评测集 80 题（其中 68 题可判）。
> 因此「达标」指**门禁值在本机本语料上被满足**，不等于线上数据，也不等于真实用户行为。
> **版本对照**：《项目定义》V1.45 /《技术方案与 MVP 设计》V1.0.47。
> **2026-10-26 增量**：图片/图表/公式解析已接入（入库期 VLM 描述 + PP-FormulaNet_plus-M ONNX）；VLM 默认关闭，
> 云端 API 必须显式放行，已有索引不回填。详见 `docs/VLM图片描述索引.md`。

## 一、业务价值：六个痛点映射到已实现的能力

| 业务痛点 | 现状代价 | 本项目给出的能力 | 已实现的可度量证据 |
|---|---|---|---|
| 交付文档写完即沉睡，找不到 | 重复写方案、跨项目踩同坑 | 混合检索 + 部门/项目/密级隔离的知识服务 | `Hit@5(strict) 98.53%`、`Recall@5(strict) 97.79%`（n=68，同轮可复算） |
| 答案不可信，人不敢用 | 拿答案还得回原文核对 | 引用强制：每条结论必带出处，无来源不出结论 | 行级引用落 gold **61/62 = 98.39%**；零引用结论 **0 条** |
| 不知道系统什么时候在瞎说 | 错误答案被当依据交付 | 无依据必拒答、证据勉强不出结论、敏感/低置信转人工 | ⑤ 四条机制：无来源不出结论 / 无依据必拒 7/7 / 敏感转人工 5/5 / 结构化首次 100% |
| 知识时效与责任人不清 | 引用了过期版本、无人负责 | 版本管理 + 人工复核闸 + 回滚 | 未经人工复核的内容**不会被引用作答**，且拒答会说清是「没资料」还是「有资料没复核」（真 HTTP 19/19 实测） |
| 权限敏感，数据不能出门 | 上云方案直接不合规 | 单机内网部署、本地推理、无外呼 | ⑥ 复跑：非回环绑定 0、宿主非回环连接 0、公网出网 0、云端兜底 False |
| 上线与否靠感觉 | 无法判断改动是变好还是变坏 | 自建评测集 + 双人标注 + 版本回归 + 可观测 | 同尺子回归对照 `delta_strict=0.0`；一条命令复验 11 阶段 |

**汇总验收状态（DoD 八条）**：达标 **3** ｜ 部分达标 **4** ｜ 不达标 **0** ｜ 不可测 0 ｜ 本次产出 1。
「部分达标」集中在两处结构性缺口：**校准（ECE 0.2006 > 0.10）** 与 **业务指标（无真实用户，只能走测试用户模拟口径）**。

## 二、Epic 与 User Story

### Epic 1 · 知识接入（Must#1：文档上传 → 准入审核 → 解析分块 → 多存储落库）

**US-1.1** 作为**交付工程师**，我希望把客户交付文档（PDF / Word）直接上传进系统，
以便项目知识不必再散落在个人网盘里。
- 验收：`POST /api/v1/documents/upload` 接收 multipart；格式白名单、**指纹查重**、密级标注缺失即告警。
- 实测：`scripts/verify_m1.py` 17 步通过；单文档摄取到可检索端到端跑通。

**US-1.2** 作为**知识负责人**，我希望系统把文档解析成结构化知识块（含表格），
以便检索命中的是"能回答问题的段落"而不是一页纸。
- 验收：**双后端按条件切换**——常规 PDF 先走文本层抽取（pypdf / python-docx），文本层薄（每页 < 40 字）或显式指定时
  转本地 **MinerU-ONNX** 后端（版面 PP-DocLayoutV2 + OCR PP-OCRv6 + 表格结构 SLANet-plus，`onnxruntime` CPU 推理，零下载）；
  **Parent-Child 分块**（子块命中；**父块正文回捞已实现但默认不启用**——用户 2026-10-22 按实测裁决，
  原句「父块补上下文」的字面实现保留为开关 `KEE_PARENT_CONTEXT_IN_ANSWER`，理由见下一条边界）。
  **图片/图表/公式（2026-10-26 新增）**：DOCX 内嵌图片、独立 png/jpg 等、文本层 PDF 内嵌图片、扫描件/图片型 PDF 均可 OCR；
  PDF `image/figure/chart` 区域可选用入库期 VLM 生成中文描述；公式区域走本地 PP-FormulaNet_plus-M ONNX 输出 LaTeX。
  VLM **默认关闭**，云端 API 必须显式 `KEE_VLM_ALLOW_REMOTE=true`；描述作为普通段落进入分块与检索，服务阶段不跑 VLM。
- 实测：OCR 与表格结构两条路径由 `scripts/verify_m1.py` 步 7.5 / 7.6 在**扫描件**上实测通过
  （表格还原父块 17 行 × 7 列 + 合并表头，子块行级「列名=值」可按单元格检索命中）；
  表格逐格真值对照由 `scripts/table_fixtures.py` 合成 PDF 提供，`tests/test_table_structure.py` 覆盖。
  ⚠ 边界：**当前 193 块语料本身是代码内置的文本文档，没走 OCR**——OCR 后端是在扫描件与真实厂商 PDF fixture 上验证的。
- 边界（如实）：**Parent-Child 的「父块补上下文」已于 2026-10-22 实现，但实测判「净负」，用户裁「默认关 + 不重切索引」**。
  子块入向量库、父块（整章节 / 整张表 / 章节内的 token 窗口）入权威源且 `parent_id` 全程可查；
  答案组装原先**只喂子块**（带 `章节标题｜` 前缀），现按需求接上父块正文回捞
  （`apply_parent_context` + `pg.parents_content`，开关 `KEE_PARENT_CONTEXT_IN_ANSWER`、预算 `..._MAX_TOKENS`；
  父块文字**不占证据编号**，所以它本身永远不会成为引用对象）。
  两轮实测都不支持启用：**2026-10-21 四档消融**（67 题、检索面恒定、A0 重跑噪声地板 2/67）
  接上父块正文**无可测收益**（可完成率 Δ −0.0299 恰等于地板、同分母落 gold 净 −1 行），
  代价是 prompt 均值 **+1219.6 tok**（此前误印「p50 +1056」，那是一处 percentile 量纲事故）、escalate **1→3 行**；
  灌**错配**父块劣化超地板（Δ −0.0597、escalate 1→5）⇒ 上一版那句「**当前不成立**」当时是准确的。
  **2026-10-22 按用户下发的 token 粒度（Child 200/30、Parent 1000/150）重测**：先量形状——该粒度在现网短章节上
  **完全不 binding**（0/73 章节会分窗、章节正文最长 293 token 对 1000 预算），所以并成 6 小节一章再测（21/25 章节分窗）；
  68 题、六条护栏全过、A0 两轮漂移 ≤0.0147 ⇒ 可完成率 **−2.0 题当量**、引用落 gold **−4.0 题当量**、转人工净增 2 道，
  唯一超地板的变好项（串落地 +3.0 题当量）**不能归因于回捞**：确实带进新答案句的 6/68 题在两档**逐题同判**（结果改变 0 道）。
  2026-10-21 的「Parent-Child vs 固定分块」长章节对照结论不变：**检索层有收益**
  （答案句覆盖 Recall@5 0.9279 vs 0.7991，+12.88 个百分点 = 8.76 题当量、3 轮轮间极差 0.0），
  **「答得更对」测不出**，只有**引用落 gold +7.36 个百分点**是有效差；
  「本语料章节短、真语料可能不同」这条免罪条款**作废**。
  **裁决（2026-10-22）**：回捞**默认关**（`KEE_PARENT_CONTEXT_IN_ANSWER=false`），本句验收措辞已按上面这段改直；
  生产索引**不按 token 粒度重切**，`chunk_granularity` 保持 `chars`（重切会让子块 id 全变 ⇒ strict gold 与
  547 行绑子块 id 的双人标注全部作废，而收益未实测）；新粒度只在显式 `KEE_CHUNK_GRANULARITY=tokens` 时生效，
  已在 scratch 上验过。证据 `reports/m1/M1_父块上下文消融.md`、`reports/m1/M1_分块策略对照.md`、
  `reports/m1/M1_父块回捞与token粒度.md`；判定闸门 `tests/test_parent_context.py::test_shipped_default_is_off_and_reads_the_field_not_the_instance`。
- 边界（如实）：**公式解析已接入，但准确率未验收**——PP-FormulaNet_plus-M ONNX 输出 LaTeX，复杂分式/矩阵结构仍可能出错；
  **图片/图表 VLM 描述默认关闭**，本地 Qwen3-VL 尚未实跑；不做图片资产存储/原图回链，也不做 CLIP/ColPali 视觉向量检索。
  完整配置与边界见 `docs/VLM图片描述索引.md`。

**US-1.3** 作为**知识负责人**，我希望重复上传同一份文档不会产生两份知识，
以便语料不会因为人员习惯而膨胀失真。
- 验收：`checksum_of` 指纹 + 准入拒绝 `AdmissionRejected`；升版必须显式带同一 `doc_id`。
- 实测：写路径 13 项在 **scratch 库 + scratch 集合**跑通（线上没有删除文档的端点，不拿生产语料试），跑完自检生产计数未变。

**US-1.4** 作为**知识负责人**，我希望未经我复核的内容不会进入答案，
以便"投毒一篇文档就污染问答"这条路径被堵住。
- 验收：复核**章落在版本上**（与 `effective/superseded` 分离，回滚不擦章）；闸在**答案层**——未复核仍可被检索（复核人得看得见），但不进答案证据面。**V1.43 起，摘光之后的拒答必须与「库里真没资料」分得开**：对外字段 `refusal_reason`（`no_evidence` / `all_evidence_unreviewed`）与 `unreviewed_evidence_count`，界面上是两句不同的人话——把“流程没走完”说成“这事无解”会误导业务决策。配套只读端点 `GET /api/v1/reviews/pending` 给出全库口径的待复核清单（按调用者可见范围过滤）。
- 实测：`scripts/m4_upload_http_check.py` 真机 **19/19**（含反面对照：真没资料不许说成待复核；复核后必须从队列消失、原因必须清空）；`tests/test_review_gate.py` 13 条（含"按版本摘不是按文档摘"反向断言）；前端 `AskPage.test.tsx` 16 条。⚠ 生产语料 24 个版本已全部复核 ⇒ **这条新出口在现网暂无对象**，实测证据全部来自 scratch 库。
- 措辞边界：对外只能说"不会被引用作答"，**不能说"不会被检索到"**；反过来，拒答时也不许把"没复核"说成"没资料"。

### Epic 2 · 检索质量（Must#2）

**US-2.1** 作为**项目经理**，我希望用一句口语化的问题就检索到书面语的证据，
以便不必知道文档里的原词才能问。
- 验收：Milvus 服务端 **BM25（jieba 中文分析器）+ 稠密向量 + RRF 融合 + BGE reranker 重排**；
  查询改写环节已实现（默认 `off`，因单步 P95 843ms 已吃满 800ms 检索门禁）。
- 实测：jieba 分析器 Recall@5 **0.7612** vs 默认分析器 **0.399**（Gate 0 ②）；主判定 `Hit@5(strict) ≥ 95%`、`Recall@5(strict) ≥ 85%` **均达标**。
- 诚实条款：报告值 `section Recall@5 = 83.74%`（95% CI [0.7754, 0.89]，n=68）**仍低于 0.85**，它按裁决只是报告值。

**US-2.2** 作为**安全管理员**，我希望某人检索到的结果天然只包含他有权看的范围，
以便部门/项目/密级隔离不依赖前端隐藏。
- 验收：过滤在**检索层唯一强制点**（Milvus filter expression + 密级/行业/项目维度），越权片段读取被拒并留审计。
- 实测：`verify_m4` 经 Nginx **13/13**、直连 **12/12**，含越权读取的拒绝与审计留痕断言。

### Epic 3 · 编排与答案可信（Must#3 / #4 / #5 / #6）

**US-3.1** 作为**使用者**，我希望答案的每个结论都能点开看到出处原文，
以便我可以复核而不是被迫相信。
- 验收：LangGraph 七节点状态机（敏感闸 → 改写 → 检索 → 检索闸 → 生成 → 引用强制 → 置信度）；引用与结论同轮产出，无来源不出结论。
- 实测：结构化输出首次成功率 **100%（58/58，被截断 0）**；行级引用落 gold **98.39%**。

**US-3.2** 作为**使用者**，我希望系统在证据不够时明确说"不知道"，
以便错误答案不以自信的形式出现在交付材料里。
- 验收：拒答 / 降级 / 转人工三类出口按**两把尺**分别判定（语料内无依据 = 结论必须为空；密级 3 敏感 = 允许答但必须转人工）。
- 实测：无依据必拒 **7/7**、敏感转人工 **5/5**、非作答题 12 题人判处置正确率 **12/12**、误拒 **0/7**。

**US-3.3** 作为**评审人**，我希望看到系统对自己答案的量化把握，
以便按把握决定复核力度。
- 验收：置信度已降格为**复合规则分**，响应自带 `score_basis=rule_composite_not_probability`；温度维持 T=1.0、不称概率。
- 实测（真人标签，第一个有方差的正确性标签）：`answer_prod` n=62，accuracy **0.9677**、mean_conf 0.7671、**ECE 0.2006**、AUC 0.7833（CI 0.627–0.914）。
- 诚实条款：**ECE 0.2006 > 0.10 ⇒ 这一格不达标**（方向为欠置信，不是危险的那一边）；7 行错行为按层归因后**没有一行是校准能救的**。

### Epic 4 · 流式与多轮（Must#7）

**US-4.1** 作为**使用者**，我希望答案逐字出现而不是转圈等待，
以便长答案能提前判断方向是否跑偏。
- 验收：**token 级流式**经 SSE 推送；一次 JSON 生成即可逐段推送（从未闭合信封按路径读已成形字段）；撤回的片段在界面上不静默消失。
- 实测（净环境，n=24）：首个**可读字** p50 **695.4ms** / p95 **859.2ms** / max 1008.6ms；`first_visible_ms` 口径已写进门禁文字。

**US-4.2** 作为**使用者**，我希望可以就上一个答案继续追问，
以便不必把背景重新拼进一句问题里。
- 验收：会话轮次 + 多轮指代消解；状态由 LangGraph 承载，历史记录持久化并可刷新恢复。
- 实测：`m3_multiturn_probe` **14/14 发生消解**；检索层面把 q-003 从 0.0391 救回 0.9697（答案层因密级正确地不给结论——两层分开报）。

### Epic 5 · 权限与审计（Must#8）

**US-5.1** 作为**系统管理员**，我希望账号、角色、会话都可管理且可强制下线，
以便离职或异常令牌能立即失效。
- 验收：登录/注册/角色分配/撤销全部会话端点；口令 **scrypt**、令牌仅存 **SHA-256 摘要**；请求头冒充身份通道**默认关闭**。
- 实测：`verify_m4` 治理端点权限面断言 + `tests/test_auth.py`。

**US-5.2** 作为**合规负责人**，我希望"谁问了什么、看了哪段"可追溯且不可篡改，
以便事后审计与投毒排查有依据。
- 验收：审计表**追加写 + `UPDATE/DELETE` 禁改删触发器**；`TRUNCATE` 由**权限面**挡住——表与触发器函数的属主换成
  NOLOGIN 超级用户 `postgres`，应用连**非特权角色 `kee_app`**（该表上只有 `INSERT, SELECT`）。
  ⚠ 措辞要准：PostgreSQL 的行级/语句级触发器**不覆盖 TRUNCATE**，项目也**没有**用 event trigger 去补，
  而 PG 里 TRUNCATE 需要属主或超级用户身份，所以"只 REVOKE"是不够的，**属主 + 降级两件事缺一不可**。
  问答、片段读取、摄取、复核、回滚均留痕。
- 实测：`GET /api/v1/audit` + 审计事件类型 7 类齐备（含 `chunks_read`、`answer_generated` 带 stream 标记）；
  现场试探由**应用角色自己那条连接**发起（`harden_audit_store.probe_bypass`，2026-10-19 本机读数）：
  以 `kee_app`（非超级用户）执行 `TRUNCATE TABLE audit_log` 与 `DELETE FROM audit_log` **双双被拒**
  ——两条都停在**权限阶段** `InsufficientPrivilege: permission denied for table audit_log`，审计行数 1790 → 1790 一字未动。
  ⚠ 因此触发器在这里是**第二层**：应用角色没有 DELETE 权限时那条 `BEFORE UPDATE OR DELETE` 触发器根本轮不到执行；
  它的价值是防"日后有人重新 GRANT DELETE / 用属主身份操作"时仍能拦住。`verify_m1` 把闸门钉成断言
  （应用角色 `not rolsuper` + `audit_log` 属主 ≠ `current_user` + 试探前后行数相等）。
  残余风险如实保留：超级用户仍可整表抹除且审计零痕迹，故清场动作写在**表外凭据** `var/gate0/audit_reset.json`。

### Epic 6 · 交付形态（Must#9 + 一键部署）

**US-6.1** 作为**项目经理**，我希望有一个浏览器界面能完成"问—答—溯源—管理"，
以便不必让每个人都去调 API。
- 验收：Vite + React 19 + TypeScript 前端，问答页 / 知识库管理页 / 审计页 / 账号页 / 登录注册；状态条只报规模与空索引。
- 实测：前端单测 **37** 条 + `tsc -b && vite build` 干净；DOM 断言钉三态渲染与撤回不可静默删；Playwright-Edge 真机走查（1440×900，真实 HTTP）。

**US-6.2** 作为**部署工程师**，我希望一条 `docker compose up` 起整套，
以便内网机器可以在无外部依赖条件下交付。
- 验收：三份 compose（存储栈 / 前端 Nginx / 观测栈）+ Langfuse profile；Nginx 反代 `/api/`、`/healthz`、SSE 专用 location。
- 实测：⑥ 一键复跑 **1.4s 全 healthy**、非回环绑定 0、公网出网 0。
- 边界（如实）：**"整机断网下端到端问答"未证**并已划出承诺范围（`internal: true` 会同时切断宿主↔容器通路，而 API 在宿主；ADR-12 已定案维持现状）。

### Epic 7 · 评估、可观测与复验（横切）

**US-7.1** 作为**算法工程师**，我希望改动检索或生成后能自动发现质量退化，
以便不把回归留到用户投诉时才发现。
- 验收：自建评测集（80 题 / 68 可判，dev/test 半区隔离，网格只在 dev 上跑）；**版本回归闸门** `m2_eval --skip-grid` + `ruler` 尺子指纹（题量/可判行数/gold 总数/题面哈希），退出码分开报「门禁没过」与「回归」。
- 实测：`delta_strict = 0.0`、`regressed = false`；尺子变了则如实报「不可比」，**不给假的 `regressed=false`**。

**US-7.2** 作为**运维值班**，我希望看板能回答"现在慢不慢、降级多不多、权限闸拦了多少"，
以便不用登机器抓日志。
- 验收：`/metrics` 暴露 **19 个 `kee_*` 指标族**（私有注册表 + 全闭合标签，无查询文本/用户名/文档 id）；Grafana **15 面板** + Prometheus **9 条告警**；结构化 JSON 日志按 `trace_id` 串起响应/审计/会话轮次。
- 实测：`scripts/m5_observability_probe.py` 七条计数器恒等式、31 条 PromQL 逐条执行、Grafana 面板级通路全绿；埋点开销经**配对交错 A/B** 判定为不可检出。
- 口径边界（写在面板第一格）：**看板分位数不是门禁读数**（桶插值近似 + 统计全部轮次）。

**US-7.3** 作为**架构负责人**，我希望一条命令完成全量复验并复原服务状态，
以便复验不依赖某人记得按顺序跑八支脚本。
- 验收：`scripts/ci_local.sh` 十一阶段（前置 / 静态 / 后端 / 前端 / M1 / M3 / 检索回归 / 预热 / 真 HTTP 两套 / 观测探针），失败即停、日志留档、证据 md5 前后对比。
- 实测：十一阶段**全绿**，`var/gate0` 证据产物 md5 **一字未变**。

**US-7.4** 作为**评估工程师**，我希望有 Faithfulness / Answer Relevance 这类指标的可用装置，
以便"幻觉率"不是嘴上说的数。
- 验收：**自研复现**（不引 ragas 库，因其依赖闭包会顶掉硬钉的 `numpy==2.5.3` 且默认走 OpenAI 客户端）；分母为 0 报「不适用」而不是 0%。
- 实测：Faithfulness(cited) **0.9866**（n=62，CI [0.9651, 1.0]）；Answer Relevance **0.6582**（作答行档）。
- 硬边界：**均为报告值，不进门禁**；LLM 裁判与真人判 **κ = −0.0645**，一致率撑不住绝对值，故不得写成"LLM 自动评测已可用"。
